===========================================================================
 excel2mysql-cli —— Excel / ZIP / SQL 脚本 批量导入 MySQL（Windows 7 可用）
===========================================================================

这个包是命令行版，不需要安装 Python，也没有图形界面：它是控制台程序，要在命令
提示符（cmd）或 PowerShell 里带参数运行。直接双击 excel2mysql-cli.exe 会打一句
"没有输入"的用法后立刻退出（黑窗口一闪而过），这是预期行为，不是坏了——双击
不带任何参数，程序就没有可干的活。要图形界面请用图形版那个包。
同一套推断与建表逻辑与图形版（需要 Windows 10 1809+）完全一致，建出来的
表结构相同。


关于三条交付线（先确认你拿的是不是该拿的那个包）
---------------------------------------------------------------------------
同一个工具现在有三份可交付的程序，解析、类型推断与建表逻辑同源，差别只在界面、
能跑的系统、命令行开关：

  图形版 excel2mysql.exe（Python）
      要 64 位 Windows 10 1809 或 Windows 11。拖文件、改字段名与主键、看进度框，
      右上角「?」或 F1 有内置《使用说明》。

  命令行版 excel2mysql-cli.exe（Python，就是本包）
      没有界面，给路径就干活，靠日志和退出码说话。能跑在 Windows 7 SP1 上，
      但前提是那台机器的 UCRT 补丁（见下一节）和系统文件完整。

  Java 版 excel2mysql-java-*-win64
      界面与上面那个图形版逐项目等价（两份界面会被程序各自枚举成清单逐键比对），
      命令行也在同一个 jar 里。目标机器什么都不用装——Java 运行时随包带着，
      64 位 Windows 7 起就能跑。它的命令行开关与本包不同：动作由路径类型决定
      （给 .sql 就执行脚本，给目录两类都干），不需要本包那个执行开关，
      也没有本包的批量大小、日志文件、静默等开关。以那份包里的 README.txt 为准。

三份包建出来的表结构是一样的：同一批 Excel 分别喂给 Python 与 Java，表名、字段名、
类型、主键都要逐格相等才算数，这条由仓库里的差分闸门把着。

只有界面上有、命令行做不了的几件：改字段名与主键的表结构预览、
生成标准 / 简易 Excel 交付件（这两件三条线的界面里都有，本包没有）。


一、开始之前（Windows 7 的前置条件）
---------------------------------------------------------------------------
1) 必须是 64 位系统，且已装 Service Pack 1（winver 里显示 Build 7601）。
2) 必须装好 UCRT（通用 C 运行时）补丁 KB2999226。
   没装时的症状：双击后弹"由于找不到 api-ms-win-crt-environment-l1-1-0.dll，
   无法继续执行代码"或"找不到指定的程序"。这不是本程序的 bug——进程根本没起来，
   所以看不到任何日志。检查办法（cmd 里执行）：
       dir C:\Windows\System32\ucrtbase.dll
       dism /online /get-packages | findstr 2999226
   任一报"找不到"就去装 KB2999226（Windows Update 一般已自动装好）。
   本包已经带了补丁和脚本，在 win7_sp1_patch\win7_prereq_files\ 目录里：
       3.check_win7.bat        先自检：系统版本、四个补丁装没装、C 盘剩余空间
       4.install_minimal.bat   最小修复三件（KB3063858 + KB2999226 + vc_redist），
                               够本包跑起来，推荐先跑这个
       5.install_win7_prereq.bat  一次装全（再加 KB3020369 与 KB3125574 汇总）
       1.download_win7_prereq.ps1 包内文件缺失时按官方目录重新下载
       2.install_win7_prereq.ps1  与上面等价的 PowerShell 版本
   两个 .bat 都要右键"以管理员身份运行"，装完重启，再执行
       excel2mysql-cli.exe --version
   能打印版本号就说明这层通了。这几个 .msu 与 vc_redist 是微软按内部使用授权
   分发的，不随源码入库：如果包里没有 win7_sp1_patch 这个目录，就是本次没带，
   得自己备补丁包（打包时会把"带没带"明写在日志里）。
3) 要能通过网络连到目标 MySQL（默认 127.0.0.1:3306，可在 conn.ini 里改）。


二、最省事的四条命令
---------------------------------------------------------------------------
在本目录按住 Shift 点右键 -> "在此处打开命令窗口"，然后：

  1) 先看会建成什么样，完全不碰数据库（强烈建议每次都先跑一遍）
       excel2mysql-cli.exe --dry-run D:\数据目录

  2) 只测连接通不通，顺便列出能导入的库
       excel2mysql-cli.exe --check

  3) 真正导入：目录或压缩包都行，并给全部表名加前缀
       excel2mysql-cli.exe D:\数据目录 --prefix ads_ --log 导入.log
       excel2mysql-cli.exe 数据包.zip --prefix ads_ --log 导入.log

  4) 把手头的 .sql 脚本执行到目标库
       excel2mysql-cli.exe D:\脚本目录 --run-sql --prefix ads_ --log 脚本.log

  用法与参数清单随时可以看：
       excel2mysql-cli.exe --help


三、连接配置（不用每次敲参数）
---------------------------------------------------------------------------
本目录自带一份 conn.ini，程序在没指定 -c 时会自动读它，改这个文件就行：

    [mysql]
    host = 127.0.0.1
    port = 3306
    user = root
    password =
    database =

密码建议不要写进文件，改用环境变量传，用完 set 清掉：

    set E2M_PASS=你的密码
    excel2mysql-cli.exe D:\数据目录 --prefix ads_

优先级：命令行参数 > 环境变量(E2M_HOST/E2M_PORT/E2M_USER/E2M_PASS/E2M_DB) > 配置文件。
数据库名(database)留空时，任何要写库的动作都会先报错停下，不会跑半截。
日志和报错里不会回显密码。

也可以显式指定别的配置文件： -c 别处的.ini


四、支持哪些输入
---------------------------------------------------------------------------
  .xlsx          常规 Excel（2007+）
  .xls           Excel 97-2003 老格式
  .zip           压缩包，自动展开包内的 Excel；嵌套 zip 不递归；带密码会报错
  .sql           脚本文件，只有加 --run-sql 才执行，不加时只登记并提醒一句
  目录           默认递归收集上面的文件；--no-recursive 只取该目录一层

表名与字段名规则（与图形版一致，自动完成）：
  · 文件名形如「水库基础信息（dim_reservoir_info）.xlsx」
        -> 表名取括号内英文 dim_reservoir_info，表注释取括号前中文
  · 没有有效括号时，表名由文件名汉字转拼音：水库基础信息 -> shui_ku_ji_chu_xin_xi
  · 括号里只有版本号（V2 / v2 / V2_1）时版本号不算表名：订单表（V2） ->
    ding_dan_biao_v2（--initials 为 ddbv2，再加 --upper 为 DDBV2）
  · 字段名由中文表头逐音节转拼音、下划线分隔，超长自动降级为首字母
  · 整列一个值都没有时，按字段名关键字定类型（二十类按优先级排）：
    发布日期 -> DATE、有效期/到期日 -> DATE、更新时间 -> DATETIME、打卡时刻 -> TIME、
    金额类（含违约金/本金/造价/客单价/伙食费/油料费）-> DECIMAL(16,2)、
    总计/小计/合计/累计 -> DECIMAL(18,4)、
    工期/周期/时长/工时 -> INT、
    数量/年龄/序号/位次/票数/课时/人次/班次/行数/订单数/出库数/官兵数/装备数、
    心率/脉搏/剂次/环数、发数/航次 -> INT、
    播放量/访问量/下载量/粉丝数/评论数 -> BIGINT（只涨不减的大计数）、
    是否/有无/可否 -> TINYINT(1)、比率/系数/概率/配比 -> DECIMAL(18,6)、
    评分/满意度/星级/扣分/考核分/体能分 -> DECIMAL(10,2)、
    经纬度/坐标 -> DECIMAL(18,8)、
    长度/温度/强度/能耗/吨位/壁厚/振幅/噪声/总磷/开间/血糖/视力/剂量/射程/仰角/弹径/自重等计量 -> DECIMAL(18,4)，
    网址/链接/路径/短链 -> VARCHAR(512)、备注/说明/描述/留言/条款/笔录/处置情况 -> TEXT、
    名称/类别/规格/部门/职称/岗位/楼盘/品名/创建人/审核人/密级/课目/驾驶员/状态 -> VARCHAR(255)，
    其余照旧 VARCHAR(64)；文本档只放宽不收紧（不收成 VARCHAR(32)）；
    血压/血型/过敏史/"整改期限"/"口径"这类故意不收（里面装的是 "120/80"、"A 型"、"3 年"，
    而"口径"一个词两种含义——统计口径是一段文本、炮管口径才是毫米数，判成哪一档都会有一半的表建错；
    收成数值或日期会让写入报错），付款单位/缴费方式/收费标准这类钱味词根在中间的按结尾否决金额；
    每条都会写进"类型修正"日志行
  · 类型与精度按全量数据推断（三位小数就出 DECIMAL(7,3)，不会圆成两位）
  · 自动挑主键；同一批里表名撞了自动加 _2、_3，不会互相覆盖
  · 第一个 Sheet 顶部的标准两行合并表头自动压成「父-子」一行（技术公司 + 小计 ->
    技术公司-小计），日志写"合并表头按 2 行展开"；只认这一种形态：
    合并区都从第 1 行起，且只跨两行的单列或只横跨第 1 行的多列
  · 其余合并区（数据行、其他 Sheet、单行表头、三行表头、子行合并、2x2 块）
    直接拒绝导入，日志给具体位置；只拒绝该文件，不中断整批，同批其他文件照常处理


五、常用开关
---------------------------------------------------------------------------
  --dry-run          只解析并打印建表语句，完全不连库
  --check            只连接并列出可导入的库名
  --run-sql          把 .sql 执行到目标库（每个文件一个事务）
  --prefix ads_      给全部表名加前缀。分隔用的下划线要自己写上；
                     已经以 ads_ 开头的表视为"已带该前缀"跳过，重复跑是幂等的
  --swap-prefix dim  换掉表名第一个下划线之前的首段：ods_t_order -> dim_t_order；
                     名里没有下划线的表不改，会在日志里逐条列出
  --initials         表名与字段名的汉字取拼音首字母（订单金额 -> ddje、
                     水库基础信息 -> skxxb）；默认全拼。文件名括号里显式写下的
                     英文表名不受影响
  --upper            表名与字段名转大写（订单金额 -> DING_DAN_JIN_E）；不勾时由中文
                     转写出来的名字用小写。括号里的英文表名同样转；结构定义 Sheet 里
                     手写的字段名勾上时一起转大写、不勾时按写下的原样使用；--prefix
                     给的前缀按输入原样拼接，不跟着转
  --drop-if-exists   建表前先 DROP TABLE IF EXISTS。会删掉目标库里的同名表和它的
                     数据，开启时日志会额外警告一句
  --batch N          每批插入行数，默认 500
  --log 文件名        把日志另存一份（UTF-8，追加写）。排查问题时整份发出去即可
  -q / --quiet       控制台只留警告、错误和汇总，日志文件仍记全量
  --no-recursive     目录只取一层
  --keep-temp        保留压缩包解压出的临时 Excel（默认处理完删除）
  -c / --config 文件名  指定别的配置文件（不给时自动读本目录的 conn.ini）
  --host / --port / --user / --password / --database（短写 -d）
                     临时覆盖连接信息里的某一项

日志一行读完整件事，行首是符号 + 大写标签，竖线分段：

  + [OK]   成功          例：+ [OK] 导入完成 | `t_order` 共 3 行
  ! [WARN] 提醒/跳过      例：! [WARN] 数据警告 | 共 2 个值无法转换，已按 NULL 写入
  x [ERROR] 失败         例：x [ERROR] 建表失败 | `t` | MySQL 错误码 1064：...
  - [INFO] 过程信息

数据库报错会展开成"异常类型 + MySQL 错误码 + 原文"，建表失败还会把那条语句原文
打出来。注意 CREATE/DROP/ALTER 属于 DDL，MySQL 会隐式提交，不会随事务回滚。

只要单独捞错误：
       findstr /C:"x [ERROR]" 导入.log


六、退出码（批处理里按码分流）
---------------------------------------------------------------------------
       0   全部成功
       1   用法或配置错误（参数冲突/非法、配置文件缺失、未指定目标库、没有可处理的文件）
       2   有输入文件解析失败（其余文件照常处理）
       3   无法连接 MySQL，或目标库不可用
       4   有表建表或导入失败（其余表照常处理）
       5   有 SQL 脚本执行失败（该文件已回滚，其余文件照常处理）
     130   按 Ctrl+C 中止

同时出现多种问题时取最严重的一档，所以批处理里从大到小判：

       if errorlevel 5 (echo 脚本失败) else if errorlevel 4 (echo 导入失败)


七、分发与拷贝
---------------------------------------------------------------------------
· 这个目录整体拷走（或压成 zip 发出去），解压后在 cmd 里运行 excel2mysql-cli.exe
  并带上要处理的目录或文件（别双击，双击会一闪而过，见第一节）。
· exe 与同目录的 python38.dll、*.pyd、base_library.zip、conn.ini 必须放在一起，
  只拷 exe 跑不起来。
· 杀毒软件 / SmartScreen 可能对未签名的 exe 弹提示，选"仍要运行"即可。
· 目标机不需要装 Python。


八、跑不通时先查这几条
---------------------------------------------------------------------------
  · 双击没反应 / 弹"找不到 api-ms-win-crt-...dll"  -> 第一节，缺 SP1 或 UCRT
  · [连接失败] MySQL 错误码 2003                     -> 网络/端口不通，或服务端没允许该来源
  · [连接失败] MySQL 错误码 1045                     -> 用户名或口令不对
  · [连接失败] MySQL 错误码 1049                     -> 目标库不存在，先建库或用 --check 看有哪些库
  · [未指定目标库]                                    -> 改 conn.ini 的 database，或加 -d 库名
  · [合并单元格] 被拒绝导入                           -> 在 Excel 里取消表头块以外的合并区后重新处理
  · [数据警告] 已按 NULL 写入                         -> 该列里混了非数值内容，把列类型改成文本再导
  · 表建了但数据没进去（错误码 1062/1406 等）           -> 日志里有那条语句原文和错误码，按提示改表结构或数据
