# Java 侧依赖选型：先选型，再动手

## 核心规则

**默认先找现成的。** 引入一个维护良好的第三方 jar 是正常工程手段，不是失败；手写解析器、
编解码器、协议实现之前，必须先证明"没有候选过闸"。但依赖也不能随手加：本项目的交付形态
是单胖 jar 加随包绿色 JRE 8，目标机可能离线、可能是 Win7，所以候选必须同时过下面七道闸。

## 七道闸，缺一即淘汰

- 稳定版：只认 GA/stable；禁 alpha、beta、RC、M1、SNAPSHOT、`LATEST`、版本区间
- 仍在维护：18 个月内有稳定版，安全相关收紧到 12 个月。多年没更新默认淘汰，只有
  "功能已完成、无未修 CVE、源码可接手、使用者面大"四条同时成立才可例外，
  并把例外理由写进 pom 注释
- Java 8：必须能在 `C:\Program Files\Java\jdk1.8.0_202` 下编译运行；
  "支持 Java 8 的最后一个版本"要写清，别让下次升级时误升
- 许可证：单 jar 分发属于静态合并，禁 GPL / AGPL / LGPL 及许可不明，只用可再分发许可
- 离线形态：不得有 native、不得运行时联网、不得写注册表、不起守护线程；
  传递依赖必须能 shade 进一个 jar，并在 Win7 加绿色 JRE 8 上跑得起来
- 体积：连同传递依赖的增量超过约 2 MB 要单独写理由；用不到的可选依赖显式 `<exclusion>`
- 安全与可验证：先查一遍安全公告；无遥测、无后台外联；行为必须能被现有用例钉住

## 依赖来源

- 只走国内阿里云镜像，不查也不连国外仓库；镜像配置与查询渠道见 `references/maven-mirror.md`
- 国内镜像查不到某个版本或构件，本身就是淘汰信号（目标机离线、镜像不全的不进交付）
- 安全公告查不到就写"待核实"，禁止把"没查到"写成"没有漏洞"，禁止编造发布日期

## 决策与验收

- 顺序固定：盘点已有能力 → 列至少两个候选（含自研）→ 过闸 → 双栈对齐 → 探针 → 落地 → 验收
- 库的输出与本项目既定语义冲突时，改库的用法或换库，不许悄悄改 Python 语义去迁就它
- 落地：版本进父 pom 的 `dependencyManagement`，app pom 只引用不带版本，pom 注释写清
  为什么选它、淘汰了谁、体积与许可的结论
- 探针要喂真实语料与边界样例，不把"文档说支持"当验证；任何一步红都不算落地
- 候选表怎么填、反模式清单见 `references/worksheet.md`

## 什么时候可以自研

- 所有候选都没过上面的闸
- 能力小且边界清楚（纯词法状态机、十分钟能穷举的规则），并且双栈要求逐字节一致
- 引进来会破坏交付形态：native、Java 8 不兼容、许可不可分发、体积失控
- 库的行为不可观测或不可控，现有金标准覆盖不了它

"自己写更放心""加依赖显得不专业""先写起来再说"都不算理由；理由要写进提交说明。

## 本项目锚点

- class 主版本闸门在 `java\构建验证.bat` 第 3 步；交付用 `maven-shade-plugin` 打单 jar
- 版本统一写在 `java\pom.xml` 的 `<properties>` 与 `<dependencyManagement>`，模块 pom 不写版本
- 现有依赖：`cn.idev.excel:fastexcel:1.3.0`、`com.mysql:mysql-connector-j:8.0.33`、
  `com.github.stuxuhai:jpinyin:1.1.8`、`org.slf4j:slf4j-nop:1.7.36`（须与 slf4j-api 同版本）
