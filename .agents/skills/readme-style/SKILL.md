# excel2mysql README 写法

## 读者只有一种

拿到交付包要干活的人。他会开的是包里的 README 和程序内《使用说明》，不会开仓库。

任何"写给下一个打包的人 / 跑测试的人 / 维护代码的人"的内容都不属于 README——
它们属于 `RELEASE.md`（构建、闸门、三端一致性）和程序内《使用说明》（交互细节）。

## 结构（八节，节名与 `W29c` 认的字面串一一对应）

1. 标题挂 `assets/app_icon.png`（`build_java_dist.py` 按这串字面核），下面一段话讲完
   干什么 + 最大卖点，再跟一个"输入 → 输出"的例子块
2. `## 1. 选哪个包` —— 场景 → 用哪个 → 系统，三列；紧跟"整目录一起拷"和
   "三个包共用同一套口径"这两句
3. `## 2. 上手` —— 图形版给点哪三步；命令行给能照抄的四条，顺序固定
   `--version` → `--dry-run` → `--check` → 真跑；再一句话讲清支持哪些输入
4. `## 3. 连接信息` —— 可直接拷的 ini 块 + 三处给法的优先级一句话 + 中文口令那条坑
5. `## 4. 三个会踩的坑` —— 只列真会踩的，表格三列：坑 | 表现 | 怎么避
6. `## 5. 退出码` —— 一句话把每个码讲完（反引号包数字），再给一行批处理判断
7. `## 6. 在 Win7 上起不来` —— 缺 UCRT 的症状 + 包内两支修复脚本名
8. `## 7. 再往深` —— 三行指针：交互细节去《使用说明》，SQL 示例去「SQL 执行器」页，
   构建测试去 `RELEASE.md`
9. `## 8. 许可` —— 一行

节名要连着序号写（`W30` 靠 `^## \d+\. 退出码` 定位那一节），改节名等于改守卫，
必须同一次提交。

## 不许出现

- 版本号与版本化产物名：`vX.Y.Z`、`excel2mysql-X.Y.Z.jar`、`*-win64` 一律不写。
  版本口径唯一来源是 `version.py`，由窗口标题 / `--version` / 随包 appinfo 自己报，
  README 不复制它。要写路径就写 `启动.bat`、`excel2mysql-cli.exe` 这种与版本无关的名字。
  这条现在由 `W29e` 与 `build_java_dist.py` 反向核（"出现了就红"，不是"没出现就红"），
  所以 `T15` 的站点表里也没有 README 了——别把版本号又写回去
- 测试数字与通过率、对撞键数、示例条数这类会变的数
- 构建闸门步骤、打包脚本名、`--fast` / `--no-parity` / `--keep-cache` 这类打包期开关
- 产物目录布局（`_internal`、平铺 vs onedir、文件数与 MB）
- 代码维度的改动与内部实现名（函数名、模块名、类名）
- "与 GUI 同一批函数""一字未改""同源""机器判定""差分对平"这类自证句
- 架构取舍的论证，以及对"口径怎么钉死"的解释

## 硬指标

| 项 | 要求 |
| --- | --- |
| 篇幅 | 全文 2000～3200 字符（含 markdown 符号），`W29c` 按这个区间核；宁可短 |
| 首屏 | 前 40 行读完就能动手，不出现任何实现细节 |
| 加粗 | 只标坑和用户真会踩的点，全篇 ≤ 10 处，多了就失效 |
| 代码块 | 只放能直接抄的东西：命令、ini 模板、退出码判断。`bat` 块里注释用 `rem`，`#` 在 cmd 里会报错 |
| 表格 | ≤ 4 列；不表套表、不脚注套脚注 |
| 排版 | 中英文之间留一个空格 |
| 事实 | 不发明没有的能力、数字、选项。界面按钮名要读真控件上的原文；例子必须原样跑得出来（写 `订单金额 → ding_dan_jin_e` 之前真跑一次推断，别凭印象写成全拼或首字母） |

## 守卫咬住的字面串（少一个就红）

| 守卫 | 咬什么 |
| --- | --- |
| `pack_test38.py` W29 | 含 `excel2mysql-cli` 的行里出现的 `--xxx` 必须是 argparse 真有的 |
| W29b | 全篇每个 `--xxx` 都真实存在（放行 Java 线的 `--no-sql` / `--no-excel` / `--gui`），且写明完整清单看 `--help` |
| W29e | 全文不许出现版本号形态的串（`vX.Y.Z`、`excel2mysql… X.Y.Z`、`.jar`、`-win64`）；`127.0.0.1` 不算 |
| W29c | 八节名齐 + 篇幅区间，这两项住在 `_pack_common.py` 的 `README_SECTIONS` / `README_LEN_RANGE` |
| W30 | 只在「退出码」那一节取反引号包住的数字，必须与 `cli.py` 的常量**完全相等** |
| W31 | 不许出现像真凭据的口令值（`改成你的密码` 这类占位算合规） |
| W31b/c | `下划线自己写`；`KB2999226`、`DLL load failed`、`只拷 exe`、`跑不起来`、`win7_sp1_patch` 与两支修复脚本名 |
| W31d | `Java 版`、`Windows 10 1809`、`三个包共用同一套`、`RELEASE.md` 在 README；`api-ms-win-crt`、`pack_test38.py` 在 RELEASE.md |
| 出包闸门 | `build_exe.py` 与 `build_java_dist.py` 读同一份常量核产物里那一份；只在一处挂断言，另一条线就等到打包才炸 |
| `build_java_dist.py` | `java.exe -jar` / `启动.bat` 那几行不许出现本包不认的开关；`--no-sql`、`--no-excel`、`--gui`、`Windows 7`、`KB2999226`、`退出码` 要写到；同样禁版本号形态 |

## 三条推论

1. 删任何字面串前先确认谁在数它：`grep -rn "README" *.py java/tools/*.py`。
   改名红 `W29c`，退出码换散文红 `W30`，脚本名丢了红 `W31c`，砍太短红出包闸门。
2. README 与它的守卫必须同一次提交。拆开必有一头是红的。
3. 守卫要跟着改严或改准，不能只是放宽到能过。本轮的两次改法可以照抄这个形状：
   `W30` 从"读表格首列"换成"读反引号数字"，判据仍是与常量完全相等，没松；
   篇幅上限从 6000 收到 3200，是收紧。新增 `W29e` 是反向核，把"不写版本号"
   从口头要求变成机器判定。
   改完必须做变异抽查：往 README 插一句 `当前版本 v1.2.3`、把某一节改名、
   把退出码那句里删掉一个码，确认对应各红一次，再逐字节还原。

## 动手顺序

1. 先跑 `pack_test38.py` 取基线，确认 W 组当前是绿的
2. 写 README；同时把被删字面串对应的守卫改掉（节名、正则、must 清单、`_VERSION_SITES`）
3. 跑 `pack_test38.py`（`.venv38` 与 `.venv` 两栈）+ `pack_test.py` + `java/构建验证.bat`，
   退出码全 0；改过字面串再加跑 `python build_exe.py --fast`，让出包那道文档检查也走一遍
4. 变异抽查一次，确认新守卫咬得住
5. README 与守卫一起提交，提交信息里写清"哪些字面串被搬走、对应改了哪条守卫"

`build_java_dist.py` 那一段只在打包时才跑到，改了它要在汇报里点明"这段本轮没实跑，
下次打包才生效"，别当成已验证。
