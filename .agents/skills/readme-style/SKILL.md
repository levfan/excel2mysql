# excel2mysql README 写法

## 读者只有一种

拿到交付包要干活的人。他开的是包里的 README 和程序内《使用说明》，不会开仓库。

写给打包的人、跑测试的人、维护代码的人的内容都不属于 README：构建、闸门、三端一致性
归 `RELEASE.md`，交互细节归《使用说明》。

## 八节结构（节名就是守卫认的字面串）

1. 标题挂图标，一段话讲清干什么 + 最大卖点，再给一个"输入 → 输出"的例子
2. `## 1. 选哪个包`：场景 → 用哪个 → 系统
3. `## 2. 上手`：图形版三步；命令行四条可照抄，顺序 `--version` → `--dry-run` → `--check` → 真跑
4. `## 3. 连接信息`：可拷的 ini 块 + 三处给法的优先级 + 中文口令那条坑
5. `## 4. 三个会踩的坑`：坑、表现、怎么避
6. `## 5. 退出码`：一句话讲完每个码（数字用反引号包住），再给一行批处理判断
7. `## 6. 在 Win7 上起不来`：缺 UCRT 的症状 + 包内两支修复脚本名
8. `## 7. 再往深`：三行指针，分别指向《使用说明》、「SQL 执行器」页、`RELEASE.md`
9. `## 8. 许可`：一行

节名连着序号写（守卫靠 `^## \d+\. 退出码` 定位那一节），改节名等于改守卫，必须同一次提交。

## 不许出现

- 版本号与版本化产物名：`vX.Y.Z`、`.jar` 全名、`-win64` 一律不写，版本口径只由
  窗口标题、`--version`、随包 appinfo 报
- 会变的数：测试条数、通过率、对撞键数、示例条数
- 构建闸门步骤、打包脚本名、`--fast` 这类打包期开关
- 产物目录布局（`_internal`、平铺还是 onedir、文件数与体积）
- 函数名、模块名、类名这类代码维度的改动
- "同源""一字未改""机器判定"这类自证句，以及架构取舍的论证

## 硬指标

- 篇幅 2000–3200 字符（含 markdown 符号），宁可短，不要浓缩成密不透风的短句
- 前 40 行读完就能动手，不出现任何实现细节
- 加粗 ≤10 处，只标坑和用户真会踩的点
- 代码块只放能直接抄的东西；`bat` 块里注释用 `rem`，`#` 在 cmd 里会报错
- 表格 ≤3 列，一格一句话说完，不表套表
- 中英文之间留一个空格
- 不发明没有的能力、数字、选项；按钮名读真控件上的原文；例子必须原样跑得出来

## 改之前先看谁在数它

- README 被 9 条用例守卫和 2 道出包闸门按字面串核，逐条对照见 `references/guards.md`
- 找消费者：`grep -rn "README" *.py java/tools/*.py`
- 节名与篇幅区间住在 `_pack_common.py`，一处改、三条线同时生效

## 三条推论

1. 删字面串前先跑那条 grep：改名红 `W29c`，退出码换散文红 `W30`，脚本名丢了红 `W31c`，
   砍太短红出包的文档步骤。
2. README 与它的守卫必须同一次提交，拆开必有一头是红的。
3. 守卫只许改严或改准，不许放宽到能过；改完做变异抽查，三下见 `references/guards.md`。

## 动手顺序

1. `pack_test38.py` 取基线，确认 W 组是绿的
2. 写 README，同时改掉对应守卫（节名、正则、must 清单、版本号站点表）
3. 跑 `pack_test38.py` 两栈 + `pack_test.py` + `build_exe.py --fast`，退出码全 0
4. 变异抽查一次确认新守卫咬得住，再逐字节还原
5. README 与守卫一起提交，正文一行说清搬走了哪些字面串
