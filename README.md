# <img src="assets/app_icon.png" width="44" height="44" alt="excel2mysql 图标"> Excel → MySQL 批量导入工具

一叠中文表头的 Excel，拖进去就变成 MySQL 里的表：中文表头原样留作字段注释，表名和字段名自动转拼音，类型与长度按整列真实数据推断，然后批量建表、分批插入。MIT 许可。

```sql
订单金额 → 字段名 ding_dan_jin_e  COMMENT '订单金额'
```

## 1. 选哪个包

| 场景 | 用这个 | 系统 |
| --- | --- | --- |
| Win10 / 11，要边看边改表结构 | `excel2mysql.exe` | 64 位 Windows 10 1809 及以上 |
| Win7，或要写批处理无人值守 | `excel2mysql-cli.exe` | 64 位 Windows 7 SP1 及以上，系统要有 UCRT |
| Win7 也要图形界面，或数据库口令含中文 | Java 包里的 `启动.bat` | 64 位 Windows 7 及以上，Java 运行时随包 |

三个包都是整个目录一起拷，**只拷 exe 跑不起来**；三个包共用同一套解析与建表口径，选哪个只看系统新旧、以及口令里有没有中文。都不用装 Python、Java 或数据库驱动。

Java 包也能当命令行用：`启动.bat` 同级那个 jar，用包内 `jre\bin\java.exe -jar` 起，给一个目录会同时做 Excel 建表导入和 `.sql` 执行，只要其中一件就加 `--no-sql` 或 `--no-excel`，第一个参数写 `--gui` 就是开界面。

## 2. 上手

图形版：

1. 填主机 / 端口 / 用户 / 口令，点「连接并加载库」选目标库
2. 把 Excel 或 ZIP 拖进虚线区，等它解析完，在表里逐字段改列名和类型
3. 想核对结构就点「生成表结构预览」或「预览 DDL」，这两步都不写库；满意了点「开始导入」

命令行版按这四步走，前两步都不碰库：

```bat
rem 先看能不能打印版本号：能，说明系统层面进程与依赖都起得来
excel2mysql-cli.exe --version

rem 只看会建成什么样，完全不连库，逐张表输出一句 CREATE TABLE
excel2mysql-cli.exe D:\台账 --dry-run

rem 只连接并列出可导入的库名，用来确认网络与凭据没问题
excel2mysql-cli.exe -c conn.ini --check

rem 真导：批量建表并分批插入，日志同时写进 导入.log
excel2mysql-cli.exe D:\台账 -c conn.ini -d ods_data --log 导入.log
```

输入可以是一个 `.xlsx` / `.xls`、装着它们的目录（默认递归，`--no-recursive` 只取一层）、或一个 ZIP（自动展开，压缩包本身不进清单）。文件名写成 `水库基础信息（dim_reservoir_info）.xlsx` 就直接用括号里那个英文名，没写括号就整名转拼音。顶部标准的两行合并表头自动压成 `父-子`；数据区里的合并单元格一律拒绝导入，日志给出具体位置。

## 3. 连接信息

把下面这份存成程序同级的 `conn.ini`，之后每条命令加 `-c conn.ini`，口令不会留在命令历史里：

```ini
[mysql]
host = 127.0.0.1
port = 3306
user = root
password = 改成你的密码
database = ods_data
```

段名接受 `[mysql]` 与 `[connection]`。连接信息三处都能给，优先级从高到低：命令行参数 → 环境变量（`E2M_HOST` 等，日志只说取自环境变量、不回显值）→ 配置文件（不写 `-c` 会自动读程序同级那份）。`database` 留空就是只连库不选库。

**两条 Python 线的口令不能含中文**（pymysql 按 latin-1 处理），口令里有中文就换 Java 版，它走 JDBC，没这个限制。

## 4. 三个会踩的坑

| 坑 | 表现 | 怎么避 |
| --- | --- | --- |
| `--prefix ods_` 是**加前缀**，不是改名 | 基于基础表名重算，重复跑不叠加，已带该前缀的跳过 | 分隔符**下划线自己写**，末尾没写 `_` 会警告一句；想换首段用 `--swap-prefix` |
| `--drop-if-exists` | 先 `DROP TABLE`，**数据真没了**，建表语句也不随事务回滚 | 生产库别开 |
| `.sql` 默认只登记不执行 | Windows 命令行版要显式加 `--run-sql` 才跑，不会静默执行 | Java 版相反，给 `.sql` 就执行，不想跑就 `--no-sql` |

完整开关看 `--help`。同一批里两个文件算出同名表时自动加 `_2`、`_3`，不会互相覆盖；`--quiet` 让控制台只留警告和汇总，日志文件仍记全量。

## 5. 退出码

`0` 全成功；`1` 用法或配置错，含参数冲突、配置文件缺失、没给目标库、没有任何可解析的文件；`2` 有文件解析失败，其余文件照跑；`3` 连不上库或目标库不可用；`4` 有表建表或导入失败，其余表照跑；`5` 有脚本失败并已回滚该文件，其余文件照跑；`130` 是 Ctrl+C，已完成的表与文件保留。

多种问题并存时取最严重的一档，批处理里从大到小判：

```bat
if errorlevel 5 echo 脚本失败，去看 导入.log
```

## 6. 在 Win7 上起不来

九成是系统缺 UCRT（补丁 KB2999226）：症状是 `--version` 都打不出来、弹 `ImportError: DLL load failed` 之类的报错。先跑包里 `win7_sp1_patch\3.check_win7.bat` 自检，再以管理员运行 `4.install_minimal.bat` 补齐，重启后回到 `--version` 这一步。能出版本号但 `--check` 报错且带 MySQL 错误码，那是网络或口令，跟机器无关。
