# Excel → MySQL 批量导入工具

**当前版本 v2.1.2** —— 版本号的**取值**唯一来自 `version.py` 的 `APP_VERSION`（窗口标题、程序内《关于》、
`--version`、随包 appinfo 都从它读）。但另有 8 处**写死的字符串**必须跟着一起改：三个 `pom.xml`
（根 pom 的 `<version>` 与 `<app.version>`、app/verify 的 `<parent><version>`）、
`java/构建验证.bat` 里的 jar 名、随包说明与 `java/assets/conn.ini` 注释里的示例命令、
以及本 README 顶部与几处路径示例。漏一处就是"关于框已经是新版本、jar 还叫旧版本"这种交付事故，
所以用例里有一条 `T15` 逐处把这些字符串与 `APP_VERSION` 核一遍（改版本前先跑它，改完再跑一次）。
版本号可以带开发阶段后缀（`1.1.0-alpha.1` / `-beta.1` / `-rc.1`），后缀同样只写在 `version.py` 一处，
上面那 8 处与产物名会自动带过去；**默认不带后缀**——发到现场机器的包不该自称"候选"，
什么时候才用后缀见 `.agents/skills/git-commit/SKILL.md` 的「按开发阶段命名版本」。
运行环境要求见下方「运行环境要求」一节：图形版要 **64 位 Windows 10 1809+ / Windows 11**；
必须在 Windows 7 上干活，用同一份 `core/` 的**命令行版**（见「Windows 7 命令行版」一节）。

把几十张关系型数据库导出的 Excel（中文表头）批量导入指定 MySQL 库：
- 自动建表（InnoDB），**字段注释 = 中文表头**
- **文件名智能解析**：形如 `北京市水务局-水库基础信息（dim_reservoir_info）.xlsx` 的文件，
  **表名 = 括号内英文** `dim_reservoir_info`，**表注释 = 括号前中文** `北京市水务局-水库基础信息`
- **默认表名**：无有效括号时，表名由文件名汉字自动转拼音生成，
  符合 MySQL 命名规范（小写字母/数字/下划线），每个拼音音节用下划线分隔便于阅读，
  如 `水库基础信息.xlsx` → `shui_ku_ji_chu_xin_xi`
- **表名前缀**：输入前缀一键批量应用到全部表名（如 `dim_`）；
  另有「替换首个前缀」把已有首段换掉（`ods_t_order` → `change_t_order`）
- 字段名由中文表头逐音节转拼音、蛇形命名，超 30 字符降级为首字母；类型智能推断，导入前可预览/手改
- 拖拽批量导入，进度条 + 日志，单表失败不阻断其余
- **支持 ZIP 压缩包**：直接拖一个 zip 进来，自动展开包内的多个 Excel 逐表导入
- **支持 `.xlsx` / `.xls`（97-2003 老格式）**，`.xls` 由 `xlrd` 解析
- **两行合并表头自动压成一行**（`技术公司` + `小计` → 表头 `技术公司-小计`），
  表头块以外的合并区照旧拒绝导入，日志列出具体位置
- 添加完成后**弹窗汇总**本次加了几项、其中 xlsx / xls 各多少，有失败或重复时一并报出

## 运行环境要求

本项目现在有**三条发布线，共用同一套口径（解析、类型推断、DDL、导入逻辑）**：
Python 侧同源靠同一个 `core/` 包，Java 侧是把 `core/` 重写一遍后用金标准差分对平。

| | 图形版（GUI） | 命令行版（CLI，Windows 7 专用） | Java 版（GUI + CLI 同一个包） |
| --- | --- | --- | --- |
| 入口 | `main.py` → `excel2mysql.exe` | `cli.py` → `excel2mysql-cli.exe` | `java/` → `启动.bat`（界面）／`jre\bin\java.exe -jar`（命令行） |
| 能跑的系统 | **64 位 Windows 10 1809+ / Windows 11** | **Windows 7 SP1 及以上**，且系统 UCRT 补丁与系统文件完整 | **64 位 Windows 7 及以上**；包内自带 Java 8 运行时，目标机器不用装任何东西 |
| 语言与依赖 | Python 3.10+（本机 `.venv` 用 3.12.8）+ PySide6 | Python 3.8.10（本机 `.venv38`），不含任何 Qt | Java 8（本机 `jdk1.8.0_202`），依赖见 `java/pom.xml` |
| 打包闸门 | `一键打包-图形版.bat` → `build_exe.py` | `一键打包-命令行版.bat` → `build_exe38.py` | `java/一键打包-Java版.bat` → `tools/build_java_dist.py` |
| 用例与守卫 | `pack_test.py`（518 项，含 GUI 各组；没设数据库凭据时 512 通过 / 6 跳过） | `pack_test38.py`（257 项，含真库读写与 `.sql` 执行；同一份在旧栈与新栈各跑一遍，旧栈 243 通过 / 14 跳过） | `java/构建验证.bat` 十步闸门 + `java/界面双端对撞.bat` + `--gui --selftest` |
| 交互方式 | 拖文件 / 点按钮 / 看进度框 | 给路径 / 看一行一条的日志与退出码 | 两种都有：同一个 jar，`--gui` 起界面，不给 `--gui` 就是命令行 |

三条线各自的环境与产物互不影响：GUI 包该多大还多大（162 MB）、该要 Win10 还 Win10；
命令行包不含任何 Qt，产物 131 MB（其中 42 MB 是随包的 Win7 前置补丁），能在 Windows 7 SP1 上跑；
Java 包 232 MB，绝大部分是随包的运行时。

### 四条运行形态、三个构建产物

数"线"有两种数法，容易争，这里把口径钉死：**按运行形态数是四条，按构建产物数是三个包**。

| 运行形态 | 怎么起 | 属于哪个产物 | 构建脚本 |
| --- | --- | --- | --- |
| Python 3.12 图形界面 | 双击 `excel2mysql.exe` | `dist\excel2mysql\` | `一键打包-图形版.bat` |
| Python 3.8 命令行 | `excel2mysql-cli.exe <路径>` | `dist\excel2mysql-cli\` | `一键打包-命令行版.bat` |
| Java 图形界面 | 双击 `启动.bat`（内部就是 `--gui`） | `java\dist\excel2mysql-java-<版本>-win64\` | `java\一键打包-Java版.bat` |
| Java 命令行 | `jre\bin\java.exe -jar excel2mysql-<版本>.jar <路径>` | **同一个包**，不给 `--gui` 就是命令行 | 同上（不单独出第二个包） |

两个事实要说清：Java 的界面与命令行**是同一个 jar 的两种模式**（`Main-Class` 是
`com.excel2mysql.Main`，看到首个参数 `--gui` 就转 `GuiMain`），所以不产生两份 232 MB 的包；
Python 3.8 那条**只有命令行**（`.venv38` 里没装 PySide6，实测确认），
`cli.py` 本身在 3.12 上也能跑（跨栈对跑用），但交付出去的是 3.8 那个包。

每个产物的随包必备件（打包脚本里逐条硬校验，缺一件就不出包）：

| 产物 | `conn.ini` | 操作手册 | 手册在项目侧的源文件 |
| --- | --- | --- | --- |
| 图形版（Python） | 不需要（连接信息在界面上填） | `README.txt`（完整 15 章） | `help_doc.py` → `export_manual_txt.py` 渲染 |
| 命令行版（Python） | 有 | `README.txt`（前置条件、四条命令、开关、退出码、排错） | `assets/README.txt` |
| Java 版（界面 + 命令行） | 有 | `README.txt`（快速上手与命令行）+ `使用说明.txt`（完整 15 章） | `java/assets/README.txt`（脚本填 `{version}`/`{jar}`/`{stubs}`/`{size}` 四个占位）；完整手册同由 `export_manual_txt.py` 渲染 |

图形版那份手册**不是另写一遍**：它由内置《使用说明》的 `help_doc.py` 渲染出来，
闸门再核"每个章节标题都在手册里、没有残留 HTML 标签"，所以界面里的说明和随包的文本
不会各说各话。为什么要随包带一份文本：现场拿到包的顺序是先翻文件、再决定要不要双击 exe，
只把说明藏在程序里，等于在一台可能根本起不来的机器上不给任何说明。

### 三条线的功能区别

选型只看三件事：**界面要不要、机器是什么系统、要不要写进批处理**。

| 能力 | 图形版 | 命令行版 | Java 版 |
| --- | --- | --- | --- |
| 拖文件 / 点击虚线区选文件 / ZIP 展开 / `.xlsx` 与 `.xls` | 有 | 有（给路径） | 三种输入都有，界面与命令行各一套入口 |
| 表名拼音、批量应用前缀 | 有 | 有（`--prefix`） | 有（界面两个按钮 + `--prefix`） |
| 替换首个前缀 | 有 | 有（`--swap-prefix`） | **只有界面有**，命令行没给对应开关 |
| 生成表结构预览（改字段名/类型/主键） | 有 | 无 | 有 |
| 预览 DDL | 有 | 有（`--dry-run` 打印） | 有（界面 + `--dry-run`） |
| 生成标准 / 简易 Excel 交付件 | 有（Excel 导入页 + SQL 脚本改名页） | 无 | **只有界面有**（同样两页各两颗） |
| 执行 `.sql` 脚本 | 有（SQL 脚本改名页；SQL 执行器页的脚本清单） | 默认只登记，加 `--run-sql` 才执行 | **动作由路径类型决定**：给 `.sql` 就执行，`--no-sql` / `--no-excel` 各自排除；没有 `--run-sql` |
| 批量脚本清单（拖入多选、按顺序、每文件一个事务、可选先 DROP） | 有（SQL 执行器页；命令行没有这一步，直接执行） | 一批路径交给 `--run-sql`，没有界面清单 | 有（SQL 执行器页；命令行同样直接执行） |
| 直接敲一段 SQL 执行（建库、建表、查元数据、治理体检） | 有（SQL 执行器页，带 100 条示例） | 没有界面，只能给 `.sql` 文件（`--run-sql`） | 有（SQL 执行器页，同一份示例） |
| 连接信息怎么给 | 界面上填，或同级 `conn.ini` / `E2M_*`（启动后在后台自动连接并选库） | `--host/--port/--user/--password/-d` 或 `E2M_*` 或配置文件 | 同级 `conn.ini` 或 `E2M_*`（启动自动连接；命令行只认 `-c` 指定配置文件） |
| 口令里能有中文吗 | **不能**（pymysql 按 latin-1 编码口令） | **不能**（同一个驱动） | 能（JDBC 支持 Unicode 口令） |
| 随包使用说明 | 内置《使用说明》（右上角「?」/ F1） | 包内 `README.txt` | 界面内置同一份《使用说明》 + 包内 `README.txt` |
| 其余命令行开关 | — | `--initials` `--upper` `--drop-if-exists` `--batch` `--no-recursive` `--keep-temp` `--log` `--quiet` `--check` `--dry-run` | `--initials` `--upper` `--check` `--dry-run` `--prefix` `-c/--conn` `--debug` `--version` `--gui` |

**图形版与 Java 版的界面是等价的**，而且这条等价是机器判定的：`java/界面双端对撞.bat`
把两条线的控件文案、按钮启用条件、弹窗文字、日志、写出的文件内容各自枚举成一份清单，
逐键比对（当前 316 项，另有 6 项"现场实测尺寸"只留档不比），任何一项不一致就红。所以"Java 版界面少个按钮"这类事瞒不住。

两条命令行线的**选项集并不相同**，别把一边的命令照抄到另一边：
`--run-sql`、`--swap-prefix`、`--drop-if-exists`、`--log` 这些只在 Python 命令行版有；
`--no-sql`、`--no-excel`、`--gui` 只在 Java 版有。各自的准确清单以 `--help` 输出和随包
`README.txt` 为准。

**Java 版是为"只能开在老 Windows 7 上"准备的**：Qt 6 要 Win10 1809+，Python 3.8 打的包
还要系统自带 UCRT（KB2999226）；JDK 8 那一代运行时链的是 `msvcr100.dll`，
随包就带着，不吃 UCRT。所以同一台没打过补丁的 Win7，命令行版可能起不来，Java 版能起。

这句"能起"的取证强度要说清：它是**按依赖契约判定**的——打包闸门逐 jar 核 class 主版本
≤52、核包内没有任何 `api-ms-win-*` 转发桩与 CRT 批文件，这几条不满足就不出包。
它不等于"在任意一台 Win7 上都实测过"。真机上如果起不来，先按包内 `README.txt`
的排错条目查（`jre\bin\java.exe -version` 能不能起、包是不是整目录拷全）。


### 为什么图形版跑不了 Windows 7

这不是"少装了某个依赖"能解决的，而是下面五条硬限制叠在一起（本机 venv 实测 + 官方文档）：

| 组件 | 最低要求 | 依据 |
| --- | --- | --- |
| Qt 6（`PySide6` 6.12） | **Windows 10 1809+** | Qt 官方《Windows 版 Qt》支持矩阵，Win7/8.1 根本不在列表里 |
| Python 3.9 ~ 3.13 | Win7 及更早**明确不可用** | python.org 下载页逐版本标注 "cannot be used on Windows 7 or earlier"，最后支持 Win7 的是 3.8 |
| `numpy` 2.5.3 | `Requires-Python >=3.12` | 已装包元数据 |
| `pandas` 3.0.6 | `Requires-Python >=3.11` | 已装包元数据 |
| `PyInstaller` 6.x | 文档写 "Windows 8 and newer" | 打包器官方 Requirements 页 |

在 Win7 上双击 GUI exe 的表现：还没进到 Python 代码就被系统拦下（缺 UCRT / API set），
报的是"找不到指定的程序 / 入口点"这类系统弹窗，**程序自己没机会给出友好提示**，
所以只能靠本节和《使用说明》的常见问题提前挡一句。

### 必须 Win7 本机跑的时候怎么办

**优先方案（不需要改造、不需要旧机器）**：换任意一台 Win10/11 机器跑图形版即可——
它只需要**网络能连到目标 MySQL**，Excel 放在共享目录一样能读，
"导入"这件事本身不必在 Win7 本机完成，目标机上也不用装任何东西。

**确实只能在 Win7 上跑**（例如数据不能出那台机器、或只有它连着内网库）：
用命令行版 `excel2mysql-cli.exe`。走的是"给同一份 `core/` 加一个无界面入口"这条路，
比给 GUI 加 PySide2 双分支 shim 小得多，也不用维护两套 Qt 代码：

- Python 3.8.10 是 python.org 明确支持 Win7 的最后一个版本；3.8 跑不了 PySide6/Qt6，
  但 `core/` 只依赖 pandas/numpy/pymysql/openpyxl/xlrd/pypinyin，全部有 3.8 可用的版本
- 界面换成命令行后不需要 Qt，也就绕开了那张支持矩阵；`PyInstaller 5.13.2` 是仍支持旧系统的版本
- 详细用法、退出码、配置文件格式见下一节「Windows 7 命令行版」

> **验收状态说清楚**：命令行版已经在 Python 3.8.10 + pandas 2.0.3 + numpy 1.24.4 这套旧栈上
> 全绿（`pack_test38.py` 在旧栈跑通 243 项、失败 0，14 项显式记 SKIP：G 组 13 项要真连 MySQL、
> 本轮没设凭据，V25 要 `PT_XLS` 指向真实 `.xls` 样本而本机没有该格式文件），
> 并且**同一份用例在 3.12 新栈上逐条一致**——这是"旧栈行为没变"
> 的实测证据，不是推测。打包闸门还会额外取证：产物里没有任何 Qt 文件、带的是 `python38.dll`、
> PE 头声明的最低系统版本不高于 6.1（Win7）。
> 但**手上没有真 Win7 SP1 机器可跑**，所以"双击就能用"这句不能拍胸脯：
> 真机验收前，本节按"已按官方支持矩阵与旧栈实测准备好，待真机确认"理解。
> Win7 需要 SP1 且装好 UCRT（KB2999226 / KB4019990），缺它同样是系统先拦下进程、程序没机会报错。

## Windows 7 命令行版（`cli.py` → `excel2mysql-cli.exe`）

给同一份 `core/` 加的无界面入口：**表名/字段名推断、类型与精度、主键选择、DDL 生成、
分批插入、ZIP 展开、合并表头展开与其余合并区拒绝，全部走 GUI 版同一批函数**，所以两边建出来的表结构一致。

### 怎么用最省事的四条

```bat
:: 1) 先只看会建成什么样，不碰数据库（现场排障、给客户预览都用它）
excel2mysql-cli.exe --dry-run 数据目录

:: 2) 只测连接通不通，顺便把能导入的库列出来
excel2mysql-cli.exe -c conn.ini --check

:: 3) 真正导入：展开压缩包、给全部表名加 ods_ 前缀、日志另存一份
excel2mysql-cli.exe -c conn.ini 数据包.zip --prefix ods_ --log 导入.log

:: 4) 把手头的 .sql 脚本执行到目标库（改成 ads_ 前缀；本来就叫 ads_ 开头的会跳过）
excel2mysql-cli.exe -c conn.ini 脚本目录 --run-sql --prefix ads_ --log 脚本.log
```

> 这四条里的 `-c conn.ini` 都可以省——产物同级默认带一份 `conn.ini`，不带 `-c` 会自动读到。
> 另外注意 `--prefix` 是**加一段**，不是改名：`--prefix ads_` 会把 `dim_region` 变成
> `ads_dim_region`，而已经叫 `ads_t_order` 的表被视为"已带该前缀"跳过（重复跑是幂等的），
> 所以别写一个和现有表名重复的前缀，那样等于没加。

### 输入

- 可以混着给：`.xlsx` / `.xls` / `.zip` / `.sql` 文件、或装着它们的目录（默认递归，`--no-recursive` 只取一层）
- 压缩包按 GUI 同口径展开：只取包内 Excel、忽略非 Excel、嵌套 zip 不递归、
  带密码或损坏的包整条报失败；日志里写成 `包名!包内路径`，能一眼看出文件从哪个包来
- 第一个 Sheet 顶部的两行合并表头会**自动压成一行**；表头块以外的合并区仍**直接拒绝**，
  日志给合并区位置和原因（不静默丢数据）

### 连接信息（三处来源，优先级从高到低）

1. 命令行：`--host --port --user --password -d/--database`
2. 环境变量：`E2M_HOST E2M_PORT E2M_USER E2M_PASS E2M_DB`
3. 配置文件：`-c conn.ini`；**不给 `-c` 时会自动读程序同级的 `conn.ini`**——
   产物目录里默认带一份（源文件 `assets/conn.ini`），拷走整个文件夹就能直接跑，
   改那个文件即可，不用每次敲 `-c`。日志会写明来源是"配置文件 …（自动发现）"；
   这份自动发现的文件要是写坏了（缺 `[mysql]` 段等），会打一条 `! [WARN] 默认配置忽略`
   并退回内置默认值，不会让整条命令起不来

```ini
; conn.ini —— 段名 [mysql]（也接受 [connection]）
[mysql]
host = 127.0.0.1
port = 3306
user = root
password = 改成你的密码
database = testdb
```

密码建议留在这份文件之外走 `E2M_PASS`：命令行参数会留在 cmd 历史和
任务管理器的进程列表里，填了口令的 `conn.ini` 也别外发（仓库里 `.gitignore` 已排除根级
`/conn.ini`，只有 `assets/conn.ini` 那份空口令模板入库）。
**日志与错误输出里永不回显密码**，只写"取自环境变量/配置文件"。

### 动作与选项

| 选项 | 作用 |
| --- | --- |
| `--dry-run` | 只解析并打印建表 DDL，完全不连库（脚本只报语句数与改写结果） |
| `--check` | 只连接并列出可导入的库名；指定的 `-d` 库不存在时报错退出 |
| `--run-sql` | 把输入里的 `.sql` **执行到目标库**：每个文件一个事务，全部语句成功才提交；不加这个开关时 `.sql` 只登记不执行 |
| `--prefix ods_` | 给全部表名加前缀（基于原名重算，重复使用不叠加）。**需要分隔符就自己写上下划线**，与 GUI「批量应用前缀」同一口径；末尾没写 `_` 时日志会警告一句。对 `.sql` 同样生效（走 GUI 脚本页那套改写函数） |
| `--swap-prefix change` | 替换表名第一个下划线之前的首段：`ods_t_order` → `change_t_order`；名里没有下划线或以 `_` 开头的**不改并逐条列在日志里**（拼音表名如 `shui_ku_...` 该用 `--prefix`）。对 `.sql` 同样生效 |
| `--drop-if-exists` | 建表前先 `DROP TABLE IF EXISTS`。**会删掉目标库里的同名表和它的数据**，开启时日志额外警告一句（只作用于 Excel 建表那条路，脚本内容不改） |
| `--batch N` | 每批插入行数，默认 500 |
| `--log FILE` | 另存 UTF-8 日志文件（追加写，可反复跑多轮） |
| `-q, --quiet` | 控制台只留警告、错误和汇总；日志文件仍记全量 |
| `--keep-temp` | 保留压缩包解出来的临时 Excel |

### 日志形态与退出码

一行读完整件事，行首是符号 + 大写分级标签，分段用 `|`，方便单独 `findstr` 出一档：

```
+ [OK] 解析成功 | 订单（ods_t_order）.xlsx → 表 `ods_t_order` | 字段 5 列 | 数据 3 行 | 主键 `ding_dan_bian_hao`（…）
! [WARN] 数据警告 | `t`.`amount`（DECIMAL(16,2)）共 2 个值无法转换，示例：第 7 行 'abc'；已按 NULL 写入
x [ERROR] 建表失败 | `t` | 目标库 testdb | ProgrammingError（MySQL 错误码 1064）：You have an error in your SQL syntax…
```

- 符号只有 `+ ! x -` 四种 ASCII：Win7 `cmd` 默认 cp936 码页，打勾打叉这类符号会变成乱码或方块
- MySQL 报错统一展开成「异常类型 + **MySQL 错误码** + 原文」，跟 GUI 版一个口径
- 建表失败的日志会附上那条 DDL 原文，并提醒 `CREATE/DROP/ALTER` 属 DDL，MySQL 隐式提交、**不随事务回滚**

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部成功 |
| 1 | 用法或配置错误（参数冲突/非法、配置文件缺失、未指定目标库、没有任何可解析的文件） |
| 2 | 有输入文件解析失败（其余文件照常处理；动作本身是成功的） |
| 3 | 无法连接 MySQL，或目标库不可用 |
| 4 | 有表建表或导入失败（其余表照常处理） |
| 5 | 有 SQL 脚本执行失败（该文件已回滚，其余文件照常处理） |
| 130 | 按 Ctrl+C 中止 |

同时出现多种问题时取**最严重的一档**（解析失败 + 导入失败 → 报 4；导入成功但脚本失败 → 报 5），
所以批处理脚本里 `if errorlevel 5 ... else if errorlevel 4 ...` 从大到小判就够了。

### 执行 .sql 脚本（`--run-sql`）

给 GUI「SQL 脚本改名」页的同一套逻辑做的命令行版，`core/sql_script.py` 一字未改：

- **识别 CREATE TABLE 的数量**：每个脚本先报一行 `脚本载入 | 建表.sql | CREATE TABLE 2 处 / 表 2 张：ods_t_order(1)、ods_t_user(1)`，
  扫一眼就知道这个包会往里塞几张表
- **语句切分**跳过字符串、反引号标识符、`--` / `#` 行注释与块注释里的分号
  （注释里那个 `;` 不会把语句劈成两段），只有注释的脚本按 1 条语句发给 MySQL，完全空白的记为跳过
- **每个文件一个事务**：全部语句成功才 `commit`；中途某条被拒就整文件 `rollback`，
  日志写明"第 几/共几条"、出错语句原文，并接着执行**下一个文件**（不阻断同批）
- **前缀改写**与 GUI 那两个按钮同源：`--prefix ads_` 会同步改 `CREATE` / `DROP` / `INSERT` / `ALTER` / `TRUNCATE`
  里的引用，已带该前缀的表自动跳过（重复跑是幂等的）；`--swap-prefix dim` 换首段，名里没下划线的不改并列出
- **编码回退**按 `utf-8-sig → utf-8 → gbk` 依次尝试，记事本"另存为 ANSI"的脚本照样读得开；
  dump 里夹着原样二进制字段、整份不再是合法 UTF-8 时按 UTF-8 替换坏字节，不会整份回落 GBK
  把中文表名与注释变成乱码
- 没加 `--run-sql` 时 `.sql` 只登记并打一条 `! [WARN]`，**绝不静默执行**（也不静默忽略）
- `--check` 与 `--run-sql` 互斥：`--check` 到"列出库名"就返回了，真同时要执行会被判用法错误，不猜意图

同一目录里既放 Excel 又放 `.sql` 时，两条动作各跑各的：Excel 走推断建表导入，
脚本走 `--run-sql`，日志里分别有 `导入汇总` 和 `脚本汇总` 两行交代。

### 表名撞了怎么办

同一批里两个文件算出同名表，会自动加 `_2`、`_3`（与 GUI 用同一个 `make_unique_names`），
所以不会发生后一张表覆盖前一张的情况。加/换前缀之后同样再去重一次。

### 拿到 Win7 真机后的最小验收（三步，别一上来就跑导入）

1. `excel2mysql-cli.exe --version` —— 能打印 `excel2mysql-cli 2.1.2` 就说明系统层面进程起得来。
   起不来（"找不到指定的程序/入口点"）基本是缺 UCRT（KB2999226）或那是 32 位系统，
   跟本工具无关，程序也没机会报错
2. `excel2mysql-cli.exe --dry-run 样例.xlsx --log 试跑.log` —— 退出码 0、日志里出现
   `CREATE TABLE ...` 与 `+ [OK] 解析成功`，说明 pandas / openpyxl / xlrd / pypinyin 词典
   在这个包里是齐的（冻结态最容易缺的就是这类运行时按名字加载的东西）
3. `excel2mysql-cli.exe -c conn.ini --check` —— 能列出库名，说明 pymysql、网络、凭据三件事都通

三步都过了再做真实导入。任何一步失败，把 `--log` 那个文件整份拿出来看，
里面的 `x [ERROR]` 行自带 MySQL 错误码，够定位了。

`ImportError: DLL load failed while importing _socket` 的现场修法：
先 `3.check_win7.bat` 自检，再管理员运行 `4.install_minimal.bat`（KB3063858 + KB2999226 +
vc_redist 三件就够本包跑起来），或 `5.install_win7_prereq.bat` 一次装全，装完重启再验
`excel2mysql-cli.exe --version`。这批文件是微软按内部使用授权分发的，也是几十 MB 二进制，
**不入库**（`.gitignore` 里明确排除）；目录不在时构建照常通过，但日志与产物说明都会明写
"本次没带补丁"，不会让使用方以为包里有。

产物同级那份 **`README.txt`**（源文件 `assets/README.txt`）是写给现场使用方的纯文本说明：
Win7 前置条件（SP1 + UCRT/KB2999226 与缺它时的症状）、四条最省事命令、`conn.ini` 怎么改、

**它有双向守卫**：用例 W29/W29b 拿 `argparse` 的真实长选项清单反着核这份文件——
写一个不存在的开关、或加了新开关忘了补说明，都会当场变红；W30 核退出码清单与代码常量一一对应，

> 冻结态测试包（`packtest38.spec`）会把各依赖的 `*.dist-info` 元数据一起收进包里
> （`copy_metadata`），这样"旧栈装的到底是不是 `requirements38.txt` 钉的那几个版本"

## 打包为 Windows 免安装 exe

**有三套打包闸门，各产一条线的包，跑在不同环境上，互不影响：**

| 产物 | 双击入口 | 实际执行 | 用什么环境 |
| --- | --- | --- | --- |
| 图形版 `dist\excel2mysql\`（162 MB，带 `_internal`） | `一键打包-图形版.bat` | `build_exe.py` → `excel2mysql.spec` | `.venv`（3.12 + PyInstaller 6.x） |
| 命令行版 `dist\excel2mysql-cli\`（131 MB，平铺无 `_internal`；内含 `win7_sp1_patch\`） | `一键打包-命令行版.bat` | `build_exe38.py` → `excel2mysql_cli38.spec` | `.venv38`（3.8.10 + PyInstaller 5.x） |

（三份产物都来自同一份源码，源码没过闸门时打出来的也是坏包）。它不接受参数，
单端自己的选项（例如 `--fast`）仍直接调对应的那个 bat。

下面「一键打包」到「已知限制」讲的是**图形版**那条闸门；

### 一键打包（推荐，改完代码就用它）

**双击项目根目录的 `一键打包-图形版.bat`** 即可。它按顺序做完并逐项汇报：

| 步骤 | 做什么 | 失败会怎样 |
| --- | --- | --- |
| 1 检查打包环境 | venv / PyInstaller / spec / 用例脚本是否齐备 | 直接中止，并给出补齐命令 |
| 2 确认产品 exe 未在运行 | 用 `tasklist` 查进程 | 中止并提示先关掉（否则文件被锁，构建必失败） |
| 3 开发态功能用例集 | 跑 `pack_test.py` 全部用例 | 中止，不给你"看起来成功"的包 |
| 4 构建产品包 | `pyinstaller excel2mysql.spec` | 中止 |
| 5 冻结态用例集 | 打一个测试 exe 并运行它，在打包环境里再跑一遍全部用例 | 中止 |
| 6 启动验收 | 真启动 `excel2mysql.exe`，等窗口出现、核对标题、用 `SendMessageTimeout` 判断界面是否卡死，关闭后确认无残留窗口 | 中止 |
| 7 清理构建缓存 | 删掉 `build/` 与 `build_packtest/`（PyInstaller 中间产物，下次构建自动重建）；`--keep-cache` 可保留 | 不影响结果 |

全部通过才打印"打包成功"和产物路径；任一步失败以非 0 退出码结束。
实测耗时约 2 分钟（两次构建各约 30 秒 + 两轮用例）。

命令行用法与可选参数：

```bash
python build_exe.py              # 完整流程（等价于双击 bat）
python build_exe.py --app-only   # 跳过冻结态用例集，但仍做启动验收
python build_exe.py --fast       # 只构建产品包，跳过冻结态用例与启动验收（图快时用）
python build_exe.py --keep-cache # 保留 build/ 中间缓存，加速下一次构建
```

要把 MySQL 真实读写（G 组）也纳入验收，先备好凭据：

```bat
set PT_HOST=127.0.0.1& set PT_PORT=3306& set PT_USER=root& set PT_PASS=密码& set PT_DB=测试库
一键打包-图形版.bat
```

未设凭据时 G 组打印 `SKIP`，并在结尾的汇总里显式记为"未覆盖"，不会被算成通过。

### spec 里的关键取舍

| 配置 | 作用 |

### 已知限制

- 杀毒软件 / Windows SmartScreen 可能对未签名的 exe 弹拦截提示，选"仍要运行"即可；
  要彻底消除需要代码签名证书
- **图形版**的打包机与目标机都需 64 位 Windows 10/11（PyInstaller 不做跨平台交叉打包，也不产出 32 位包）。
  命令行版不受这条限制：它在 Python 3.8 上打包，产物面向 Windows 7 SP1+，
  但**打包机本身仍需一台 64 位 Windows**（32 位系统要另找）
- **Windows 7 真机还没验收过**：命令行版目前的证据是"旧栈 3.8 全绿 + 新栈同口径逐条一致 +
  产物无任何 Qt + PE 头要求的系统版本 ≤ 6.1"，这些挡得住已知硬限制，
  但不等于在某一具体 Win7 SP1 上一键双击就能起（还取决于该机装没装 UCRT / KB2999226、
  是不是 32 位系统、杀软怎么配）。拿到真机后按「Windows 7 命令行版」的三步最小验证走一遍再交付
- ZIP 展开的文件落在系统临时目录（`%TEMP%\e2m_gui_*`），关闭窗口即清理；
  因此**关掉程序后**失败列表里来自 ZIP 的文件无法重试，需重新拖入压缩包
- 整数列超出 BIGINT 范围（`±9223372036854775807`）时，整张表会被拒绝并报
  `MySQL 错误码 1264 Out of range value`，事务回滚，其余表继续。Excel 的数值单元格是
  IEEE double，`9223372036854775807` 这种数在 Excel 里存的就不是它自己（会写成 2^63），
  所以要落这种量级的数，得在结构定义 Sheet 里把该列写成 `DECIMAL(20,0)`，
  或者把它当文本列导入；靠推断得到的 `BIGINT` 装不下它
- 执行 `.sql` 时，`CREATE` / `DROP` / `ALTER` 这类 DDL 由 MySQL 隐式提交，
  脚本中途失败时"本文件事务已回滚"只撤得掉后面的数据操作，已经建出来的空表留在库里。
  这是数据库的限制，两条线一样；日志会跟着打一行注意，别按"什么都没发生"去理解失败结果
- **Python 两条线的 MySQL 口令只能是 latin-1 可编码的字符**（实测 pymysql 2.2.8：
  `connections.py:314` 在握手前就把口令 `encode("latin1")`）。口令含中文时抛
  `UnicodeEncodeError`，连不上库，报的还不是数据库的错；日志里会跟着给一句"多半出在口令上"
  的指引（`core/log_text.py`）。同一条口令在 Java 版能用（JDBC 支持 Unicode 口令）——
  现场改不了口令就选 Java 版
- **`.xlsx` 的 zip 膨胀检查在 Java 线被关掉**（`ZipSecureFile.setMinInflateRatio(0)`）：
  POI 的默认阈值（0.01）会把"一整列都是同一句重复文本"的正常业务表判成 zip bomb 拒读，
  而 Python 线（openpyxl/pandas）没有这道检查。读进来的都是操作员自己给的本机文件，
  不是第三方上传物，所以宁可让一个膨胀极大的表多花几秒，也不留"读不进自己的数据"这种失败。
  代价是这道防线对真正的恶意包失效——需要挡外来压缩包时请用 Python 线

### 上线前的一次验收（三条线通用）

按顺序走，每一步都要在日志里看到对应的行；没看到就停下来查，不要跳过。
下面用命令行线写，图形版是同一批检查在界面上点一遍（连接并加载库 → 点击虚线区选文件 →
生成表结构预览 → 开始导入）。

1. 只测连接：`--check`。预期 `+ [OK]` 打出库清单，退出码 0。
   这一步证明的不是"能连上"，而是这台机器上的口令与前缀环境变量真的传进去了
2. 只看不写：`--dry-run` 指向正式的目录。预期逐表打出
   `- [INFO] TABLE | 文件 … | 表 … | 模式 normal|structured | 行数 N` 与建表语句，
   有 `.sql` 时再打 `脚本载入`、`脚本前缀`、`脚本预览` 三行。
   核对三件事：表名（前缀加没加上）、每列类型与长度、主键选的是哪一列
3. 小样本试导：挑一两张小表，带一个只在测试库上的前缀（如 `--prefix e2mtest_`）正式导入。
   预期 `+ [OK] 汇总 | 表 1/1 导入成功，写入 N 行 | … | 退出码 0`。
   再回库里 `SELECT COUNT(*)` 与 `LIMIT 5` 抽查一遍——日志写"写入 N 行"是它自己数的，
   回查才是落库的证据
4. 正式跑整个目录。看最后那行汇总与退出码：`0` 全成 / `1` 用法 / `2` 解析失败 /
   `3` 连不上库 / `4` 建表或导入失败 / `5` 脚本失败。
   非 0 时日志会写明是哪张表、第几行、MySQL 错误码，按上面两条限制先判是不是预期内的拒绝
5. 复盘留痕：命令行线的日志文件路径打在最后一行（`- [INFO] 日志文件 | …`），
   图形版不写日志文件，窗口底部的日志区可选中后 Ctrl+C 复制。
   跑第二遍要注意"表已存在"的行为差异：
   命令行 Python 线有 `--drop-if-exists`，Java 线没有这个开关，
   要覆盖重跑就用图形版的「覆盖已存在表」勾选，或者先手工清那批表


## 使用流程

1. 打开软件：两个图形界面启动时会先找**程序同级的 `conn.ini`**（Java 交付包已带一份，
   图形版可从 `assets/conn.ini` 复制一份改），或读 **`E2M_*` 环境变量**；
   只要其中一份配置存在**且写了 `database`**，**窗口显示出来后就在后台自动连接**，
   服务器上有这个库就直接选中它（日志 `[连接中] 启动自动连接 …` →
   `[已加载] 目标库按 conn.ini 选中：…`）；没写 `database` 时只预填表单、不自动连
   （随包空模板属于这种，新装机器上不会平白多一条失败日志），
   两份都没有时同样不连，照常起界面、只提示一句怎么预填。
   自动连接**不挡界面**，失败**只写日志、不弹窗**，顶部状态栏保持红色告警，
   点「设置数据源信息」展开表单可手动重试。
   要换库、或没有配置时，仍按原路走：点「设置数据源信息」展开五行表单、填好后点
   「连接并加载库」、在下拉里选库；这一块默认收起成一条状态栏（只报"现在是哪个库"），
   选定库之后自动收起（详见下方「连接区」）；
   优先级是
   **环境变量 `E2M_HOST/E2M_PORT/E2M_USER/E2M_PASS/E2M_DB` > `conn.ini` > 内置默认值**，
   界面上手填的最即时。启动日志写明这次用的是哪来的配置——读到了报路径，
   文件写坏了报"找到了但读不了"并退回默认值，没有这个文件也照常起界面、只提示一句。
   这条与命令行线同一份实现（Python `core/conn_config.py`、Java `core/Config.java`）；
   口令写进文件就要看好那份文件，不想落盘就用环境变量传。
   顶部那条状态栏写 `● 目标库 库名`（主机、端口、用户名收在鼠标悬停里），
   三个页签顶部还各有一条指向（绿色写 `目标库：库名 ——`，后半句按页分工各说各的去向）；
   **没选库时只有状态栏一条红色告警**，页内三条先隐藏，选定库后再出现；切库、改主机或改端口全部实时联动刷新，
   导入/执行前扫一眼即可确认没写错库
2. 把 Excel 文件（`.xlsx` / `.xls`）或 ZIP 压缩包拖入虚线区域，或点一下虚线区批量选择
   （文件名框里输入或粘贴文件夹路径后回车，会直接进入该目录，不会把目录当成文件加进来）；
   添加完成后弹窗汇总本次结果（见下方「添加结果弹窗」）
3. 需要统一命名时，在「表名前缀」框输入内容后二选一：
   点「**批量应用前缀**」在表名前面加一段（如 `dim_`，留空再点则移除）；
   点「**替换首个前缀**」把表名第一个下划线之前那段换掉
   （填 `change` → `ods_t_order` 变 `change_t_order`，`adb_table2` 变 `change_table2`；
   表名里没有下划线的不动，末尾下划线不用写，重复点不叠加，撞名自动 `_2`）
   只想改某一张表时，在下方表格里**单击「表名」单元格**直接编辑、回车生效：
   空名、超过 64 字符、含非法字符或与其他表重名会被拦下并恢复原名，日志记一行 `[表名] 旧 → 新`；
   改过的名字成为新的基础表名，之后再加批量前缀基于它计算
4. 表格中确认每张表的**表名 / 字段名 / 类型 / 长度 / 注释 / 主键**，主键在结构预览中勾选
   （第一列「序号」从 1 连续编到最后一行，最后一个序号就是当前待导入的表的数量；
   双击文件、表注释、字段数、数据行数、主键任一列，查看这一行对应表的字段结构）
5. 点「生成表结构预览」看 DDL，确认无误后点「开始导入」
6. 底部日志区看逐表结果与耗时
7. 导入成功的文件自动从待导入列表移除，失败文件保留在列表中，可调整后重新导入

不入库、只要文件的场景：列表解析好后点「开始导入」右侧的
「**生成标准excel文件**」或「**生成简易excel文件**」，把当前这批表再写出一份 Excel 交付件
（详见下方「导出标准/简易 Excel 交付件」）。两者都不连库、不改动列表。

界面上任何一步都可以点**右上角的「?」**（或按 **F1**）打开内置的《使用说明》：
左侧目录点章节即跳转，右侧是可整篇滚动的正文，覆盖三条交付线的功能区别、
文件类型、命名与类型推断规则、主键、进度框与取消语义、日志读法、常见问题等
——不装 Python、不联网也能查。Java 版的说明窗是同一份正文（由 `help_doc.py`
导出成 `HelpDoc.java`），所以这两条线的《使用说明》不会各写各的。

## 连接区：跑业务时收起成一条，只报当前是哪个库

界面顶部那一块 `MySQL 连接信息`（主机 / 端口 / 用户名 / 密码 / 目标库）是**公共区**，
三页共用一套参数，但它不是每一步都要看的东西：真正在导数据、跑脚本的时候，
只需要知道"现在写进哪个库"。所以它的默认形态是一条状态栏，不是一整块表单。

- **收起态**：只有一行 `● 目标库 testdb`（绿色），右边一颗**「设置数据源信息」**。
  主机、端口、用户名收在鼠标悬停提示里（`testdb@127.0.0.1:3306（用户 root）`），
  信息一样都不少，只是不占首屏
- **展开态**：点「设置数据源信息」把五行表单摊开，改完点**「连接并加载库」**测连接并列出库，
  行尾那颗**「收起」**随时能手动收回去；「设置数据源信息」和「收起」不会同时出现
- **什么时候自动展开 / 收起**：程序启动就是收起的，首屏只留一条状态栏；
  配了 `conn.ini` 或 `E2M_*` **且写了 `database`** 时，窗口显示后会在后台自动连接一次（不挡界面），
  连上就按配置里的 `database` 选中目标库，状态栏由红转绿——等于替用户点了「连接并加载库」并选好库；
  没写 `database` 只预填表单、不自动连（空模板不制造失败日志）；
  自动连接失败只写日志、不弹窗，状态栏保持红色，展开后手动点一次即可重试；
  还没有目标库时那条是红色告警，直接指向「设置数据源信息」那颗按钮；
  点「连接并加载库」把列表拉出来那一下**不收起**——用户下一步就是在那个下拉里挑库，
  这时候收起等于把要用的东西藏起来；真正**选定一个库之后才自动收起**。
  `conn.ini` 里预填了 `database` 的话，加载完就等于已选定，随即收起
  （配置里的库名服务器上没有时会留一行 `[跳过]`，让人手选，不静默落到第一个库）
- **没选库时说什么**：**只有状态栏这一条红色告警**，页内三条指向不重复同一句话（未选库时整条隐藏）；
  告警文案跟着当前状态换说法，展开时是"填好下面连接信息后点「连接并加载库」"，
  收起时才说"点右侧「设置数据源信息」展开后填写"，指的那颗按钮一定真的在界面上
- **三页顶部那条指向**只在选定库后出现，不再重复 host:port
  （同一句话在三个页签抄三遍是最没用的信息），
  只说这一页要写到哪：`目标库：testdb —— Excel 数据将导入到这个库` /
  `—— 改好表名后的 DDL 执行到这个库` / `—— 编辑区里的 SQL 将执行到这个库`；
  它与状态栏同一次刷新，切页签、切库、改主机端口都一起变
- 状态栏和三页提示条都**可以按住拖选再 Ctrl+C**（Python 是开了
  `TextSelectableByMouse` 的 `QLabel`，Java 是不可编辑无边框的 `HintLabel`），
  要抄库名去别处核对不用靠眼睛记
- 两栈同一形状：Python `MainWindow.conn_bar` / `conn_form` / `set_conn_expanded`，
  Java `MainFrame.buildConnectionBar` / `setConnExpanded`；对撞键
  `conn.state`（那条文字本体）、`conn.expanded`（展开/收起）、`conn.edit`
  （「设置数据源信息」显不显示）都从真控件上读，不是各抄一份常量

## 使用说明对话框（「?」/ F1）

- 入口：主窗口**右上角「?」**按钮（贴在标题栏下方最右侧）、**F1**；说明窗内 **Esc** 或「关闭」退出
- 内容全部写在 `help_doc.py` 的 `SECTIONS` 里，每节是 `(锚点 id, 目录标题, HTML 正文)`；
  `ui_help.py` 负责渲染成"左目录 + 右正文"，正文拼成一份带锚点的长文档，点目录即 `scrollToAnchor`
- **Java 版走的是同一份正文**：`java/tools/export_help_java.py` 把 `SECTIONS` 原样导出成
  `HelpDoc.java`（改文案改 `help_doc.py` 再重导，别手改那个 Java 文件），
  所以"三条线与选型"这类章节两条线同时有。防分叉靠两处断言：Java 侧 `GuiMain`
  核目录条数（当前 15 章，改了 `help_doc.py` 忘了重导就变红），并且按**标题**而不是
  序号找章节做跳转断言（插一章不该让守卫假红）；Python 侧 P 组的条数直接从
  `SECTIONS` 取
- 排版只用 Qt Rich Text 认得的 CSS 子集（表格边框、代码块底色、`.tip` / `.warn` 提示条），
  不认的属性写了也不生效，所以样式表里只保留能生效的那部分
- **文档漂移有守卫**：用例 P 组会检查说明里点名的每个按钮在界面上真实存在、
  每个界面按钮都被说明覆盖到、每节标题确实渲染出来、点目录逐节滚动位置严格递增——
  改了界面文案而忘了改说明，用例直接变红
- 加一节内容只需往 `SECTIONS` 追加一项，目录与跳转自动跟上

## 弹窗尺寸与正文折行（首屏就得看得见全部文字）

目标机里最窄的一种是 1024x768 的老屏，所以两条 GUI 线共用同一套摆位规则：

- **结果弹窗的正文就是原文**：不预先往文本里插换行，横向由正文控件按**内容区右边界**
  折行（Qt 的标签、Swing 的 `JTextArea` 都会自己折），窗口拉大就跟着重排；
  纵向装不下时出滚动条，30 行报错整份都在框里翻得到。
- **弹窗按正文要多大就给多大**：宽 420~880、高 170~640（设计像素），再夹进当前屏幕的可用区。
  以前那块"至少 820x420"的地板有两个副作用：一句话的提示也摊开半屏空白，
  而且正文控件被地板顶得永远比视口高一点点，**滚动条从此常驻**——用户看到的
  "提示框太大、默认就有滚动条"是同一块地板的两面。高度必须先定宽再问"按这个宽度折完有多高"，
  按原文行数估高的话，长句在窄处多折的那几行刚好会把滚动条顶出来。
- 这条规则以前是两边各按「72 显示列 / 24 行」自己折好再显示，用户看到的却是
  "框很大、字很短就被折断"：列预算跟弹窗的实际像素宽没有任何约束关系，
  同一句「执行完成」在 Java 那颗弹窗里只排到 **55%** 的宽度（实测 691/1250 像素），
  Python 那颗排到 75%。更要紧的是为了把高度摁住，两边都得按"折出来的行"截断，
  于是那句「其余 N 行见日志」把两栈显示的正文改成了不同的话。
- **进度框仍然自己折行**：那个框尺寸固定（480x140）、没有滚动条，折与截都得自己算。
- **窗口尺寸钉在客户区**：Qt 的 `resize` 说的是客户区，Swing 的 `setSize` 说的是整个外框，
  照抄数字会让内容区小掉一条标题栏（「关于」那三行、进度框那条进度条都因此被压过）。
  Java 侧统一走 `Windows.clientSize`，Python 侧统一走 `ui_help.fit_client`。
- **打开前按当前屏幕夹一次**：客户区不小于内容要求的最小尺寸、整窗落在可用区内并居中，
  底部的按钮不会被任务栏吃掉。
- **取证分两层**：配置值（`window.want`、`dlg.*.want`、`popup.want.*`）跨线逐键比；实测尺寸受现场屏幕
  影响，记成 `env.*` 只留档不比。排版由 `popup.display.raw` 一把键钉住——两边显示的
  必须就是同一份原文（谁再往正文里插换行，这把键立刻不等）。各线自己再核一遍
  「整窗在可用区内、长句真的被折成多行、折点贴着右边界不小于 90%、一句话的提示框既小又不带滚动条」
  （`pack_test.py` 的 U 组 12 条、`GuiMain` 的弹窗段落）。
  `popup.want.short/tall/longwidth` 三把键取的是**落在夹取边界上**的样本（420x170、420x640、宽 880），
  这样两边字体度量差几个像素也不会造成假红；中间值由各线的用例自己量。
  期望值写的是量出来的相对关系与契约数字（420~880 宽、170~640 高这些配置区间），
  不是拿常量当期望值——那种断言把预算改成 400 也照样绿，咬不住东西。

## 长任务进度框（非模态 + 子线程）

所有可能跑久的操作都会弹一个进度框，**耗活的都在子线程，主线程只负责刷新进度**，
所以框始终能重绘、能点、能取消，不会出现"转圈假死"。这个框不挡住主窗口：
一个页在跑的时候，另外两个页照常能用（互斥的判据见下面"被挡下时"那条）。覆盖这些入口：

| 入口 | 页签 | 进度项口径 |
| --- | --- | --- |
| 点击选文件 / 拖拽入文件 | Excel 导入 | 每个压缩包 1 项 + 包内每个 Excel 解出 1 项 + 每个待解析 Excel 按 5 个阶段各 1 项（合并检测 / 读取工作簿 / 识别格式 / 推断类型 / 选主键） |
| 批量应用前缀 | Excel 导入 | 每张表 1 项 + 重名去重 1 项 |
| 开始导入 | Excel 导入 | 每张表 1 项 + 每个数据行 1 项（几十万行也能看到连续推进） |
| 生成标准excel文件 / 生成简易excel文件 | Excel 导入 | 每张表 1 项（一个文件一项），逐文件写日志 |
| 拖拽区 / 点击选文件 | SQL 脚本改名 | 每个文件 1 项（读盘 + 扫描 CREATE TABLE 都在子线程） |
| 保存修改后ddl脚本 | SQL 脚本改名 | 每个文件 1 项（先把显示名写进脚本，几十万行写盘不卡界面） |
| 执行修改后ddl脚本到当前库 | SQL 脚本改名 | 每条语句 1 项，按块推进（每个文件最多约 100 次刷新，避免海量信号拖慢界面） |
| 执行编辑区里那段 SQL | SQL 执行器 | 每条语句 1 项，逐条推进；每句开始之前查一次取消 |
| 执行脚本文件（清单） | SQL 执行器 | 轮到哪个文件才读盘切句，再按语句 1 项推进（每个文件最多约 100 次刷新）；文件与文件之间查取消，取消后剩余文件不再执行 |

SQL 页的两个前缀按钮不在上表：它们只改页面显示，瞬间完成，不弹进度框；
真正写脚本的动作都挂在保存/执行/生成这四颗按钮上。
执行器页的清单在开工前还不知道总语句数（脚本是逐个读的），总量会边读边涨，
进度框按"已完成项数不回退"处理：先按已切出的脚本报总数，后面的文件加入时只加分母。

行为细节：

- **实时回报**：进度条按"进度 i/N 项 · 当前文件：当前阶段"刷新，压缩包还会显示解出的是包内
  哪个文件；单个几十万行的文件解析途中也会随阶段推进，不是一根不动的条；
  总项数在开工前一次算准（压缩包只读中央目录预扫），进度条一路单向前进不会回退
- **平滑推进**：项数少时 `i/N` 只有几格，用 16ms 定时器把目标百分比逼近式补间，
  看起来是连续走动而不是跳格
- **可以取消**：取消按钮在"当前这一项做完"时生效，不会中途硬切留下半截数据——
  解析取消后已解析出的表照常进入待导入列表，弹窗首行标注「已取消，只完成了部分解析」；
  SQL 执行取消时该文件的事务**回滚不提交**（DDL 隐式提交的部分除外），后续文件不再执行；
  「SQL 执行器」取消后下一句就不执行，整批回滚，日志写
  `已取消 | 第 46/121 条未执行，本批未提交（已回滚）`
- **点 X 等同取消，不会把任务孤儿掉**：Java 那个框在 Windows 上去不掉标题栏的 X，
  所以 X 走的就是「取消」；Python 侧原来 X 直接关框、`exec()` 一返回就把任务位放开了，
  留下"框没了、线程还在写同一份列表"的状态，现在也改成 X = 取消
- **被挡下时说得出在等谁**：互斥按占用的东西判，不按页签判。三个资源位——
  `excel`（待导入列表）/ `sql`（脚本列表）/ `run`（执行器页：编辑区那段文本与脚本清单共用同一个结果区），
  一个任务登记它占哪一位，撞上才挡。
  所以 SQL 页在读几十兆的脚本时，执行器照样能跑语句、Excel 页照样能解析文件。
  两页的「生成标准/简易excel文件」各写各的输出目录（`meta_data_file_年月日` 与
  `sql_meta_data_file_年月日`），落点不重叠、同名表不会互相覆盖，所以它们不占共用位，
  两页可以同时生成。
  挡下时**同时弹窗和写日志**报出任务名、百分比、已完成项数、已跑时长、当前项，
  以及两个任务抢的是同一份什么东西，例如
  `已有任务在跑：正在执行 SQL… 37%（45/121）· 已 12 秒 · 第 45/121 条。这一步没执行——它和那个任务共用「SQL 执行器页的执行结果区（编辑区 SQL 与脚本清单共用）」，等它跑完或点进度框「取消」。`
  进度这一份账记在任务对象自己身上（不只记在进度框里），
  所以没有框的那条路（自检、原地跑）报出来的句子与真界面一模一样
- **两个框不叠在一起**：两条任务同时跑各弹各的框，第二个往右下错开一格，竖直那一步比框
  自己还高，所以两颗的「取消」都点得到。原先都居中在主人窗口上，两颗叠成一摞，
  后面那颗根本看不见——非模态改了但框叠着，等于还是只能管一件事
- **结果弹窗不占资源位**：跑完那一步弹的结果框只要你点一下确定；那条任务的位在它弹窗之前
  就已经还出来了，所以不会出现"谁都没点确定，这一页就一直显示有任务在跑"
- **并行时日志各写各页**：落界面的那几行（`[添加结果]`、生成完成、`已取消`）跟着它自己
  那条任务的面板走，不会被另一个还在跑的任务的面板接走
- **结束不留残留**：导入完成/失败/被中止后，Excel 页底部的进度条自动回到 0%
  （结果由弹窗 + 日志交代），停在 100% 会让人误读成"这一批的当前进度"；
  「清空待上传文件」同样把进度条归零
- **异常不挂框**：工作函数整体抛异常时，框照样关闭，日志红色打 `[任务异常]` 并弹窗提示

实现上的取舍：进度和日志通过 `ProgressSink` 这一个接口回报（子线程里它接到 `QThread`
的信号上，自动排队回主线程），解析/改写/执行逻辑都是**只认这个接口、不碰控件的纯函数**
（`parse_import_files` / `sql_load_task` / `sql_save_task` / `sql_execute_task` /
`table_prefix_task`），因此可以脱离 Qt 直接单测；SQL 页的显示名落脚本走
`core/sql_script.py` 的 `apply_display_renames`，也是纯函数。
模块级开关 `MODAL_PROGRESS` 在用例里置 `False`，任务原地跑完（用例不起线程、也不等框渲染），
用的仍是同一个工作函数和同一个回报接口。对应用例见 `pack_test.py` 的 **O 组**。
一个在跑的任务是一个对象（Python `TaskInfo` / Java `MainFrame.Task`）：标题、占的资源位、
进度台账、日志写哪块面板、自己那个进度框都在它身上，窗口只拿一份任务清单；
所以进度框改成非模态之后，两个任务并行时各自的日志仍写回各自那一页，不会串。

## 导出标准/简易 Excel 交付件

待导入列表里有表时，「开始导入」右侧的两颗按钮把这批已解析好的表再写出一份 Excel 交付件。
两者都不连库、不改动列表，产物落在可执行程序同级目录，每次按日期建一个子目录。
「SQL 脚本改名」页的同名两颗按钮共用这一套命名，只在目录名前加 `sql_`，
所以两页各自生成时写进的是两个不同目录，同名表不会互相覆盖。

| 按钮 | 输出目录 | 每个文件里有什么 |
| --- | --- | --- |
| 生成标准excel文件 | `meta_data_file_年月日` | 两个 Sheet：`元数据`（建表用的字段定义）+ `数据`（表头是英文字段名，下面是数据行） |
| 生成简易excel文件 | `simple_meta_data_file_年月日` | 只有一个 `数据` Sheet，给只要数据、不要建模说明的下游 |

文件名沿用解析输入时那套命名：`表注释（表名）.xlsx`，没有表注释时只留表名；
注释里的 `\/:*?"<>|` 换成下划线。一张表一个文件，一次点击产出 N 张表就是 N 个文件。

`元数据` Sheet 的七列与取值口径（与「两类 Excel 格式」里的结构定义表同一套，
所以标准件可以直接拖回本工具再导入，读回来与导出前一致）：

| 列 | 写法 | 读取端怎么认 |
| --- | --- | --- |
| 序号 | 1 起递增 | 不参与识别 |
| 字段名(英文) | 建表用的列名 | 数据 Sheet 按它对齐（大小写不敏感） |
| 字段注释(中文) | 列注释 | 落到 `COMMENT` |
| 数据类型 | 基础名，如 `VARCHAR`、`DECIMAL` | 与「长度」拼回 `VARCHAR(64)` |
| 长度 | `64` 或 `10,2` | 留空表示该类型不带长度 |
| 是否主键 | 主键列写 `是`，其余留空 | `是` → 主键（支持多字段组合） |
| 是否可为空 | 主键列写 `否`，其余写 `是` | 留空或 `是` → `DEFAULT NULL`；`否` → `NOT NULL` |

两个口径值得单独说明：

- 可空这一格必须显式写。读取端把「空」当成可空，要声明 `NOT NULL` 得写「否」；
  普通推断出来的表本来没有这个声明，导出时按建表实际会怎么做落成文字（主键列 `NOT NULL`，
  其余可空），所以回读能稳定还原。
- 日期一律写成 `2008-05-19` 这样的文本而不是 Excel 序列号，避免同一份数据在两次读写之间
  被历元换算挪走一天。数据 Sheet 的表头写英文字段名，取数却要先按英文字段名、再按中文注释
  去找数据里真实存在的列：普通推断出来的表，数据网格的列头还是中文注释（字段名是拼音），
  只按英文取会一列都取不到，写出的「数据」Sheet 全是空值，回读时全空行照旧剔除，
  产物退化成只有表头的模板。

过程与其他长任务同一套：进度按文件计项（一张表 1 项），逐文件写日志
（`- [INFO] 导出 | 正在写 名称`、`+ [OK] 导出 | 名称（17 列 / 5 行）`），
完成后弹窗把目录名原样报出来，日志同时打
`===== 生成完成：7/7 个文件，目录 … =====`（一个都没写成时按错误级标红）。
按「停止」在当前这个文件写完后停下，剩下的不写，日志与弹窗都会写明「已取消，剩余文件未生成」。

代码位置：Python 线 `core/meta_export.py`（命名、目录、七列口径只写这一处，
`main.py` 的 `meta_export_task` 直接调），Java 线 `core/MetaExport.java`（POI `XSSFWorkbook`）。
取证：`test_meta_export.py`（标准件回读逐字段比对，15 份夹具——夹具目录里 16 份 Excel 有
1 份含合并单元按拒绝跳过——加取消用例）、
`pack_test38.py` 的 V26-V34（3.8 冻结态同一套产物契约）、
Java 闸门第 9 步 `MetaDiffer`（Java 写出的文件与 Python 写出的逐格比对，30 条记录 / 2365 格）、
`--gui --selftest` 的 `meta_export` 段（按钮位置、启用条件、落点、产物形状、日志与弹窗、取消）。

## SQL 脚本改名页（第二个 Tab）

处理现成的 `.sql` 建表脚本，三步按顺序走：提取脚本里的 `CREATE TABLE` 列出表名清单
（表格那几列就是这个清单：序号 / 文件 / 原表名 / 当前表名 / 表注释，第一列的「序号」从 1 连续编到最后一行，
最后一个序号就是这批脚本解析出的建模语句总数，多个文件共用一套编号）→ 按清单批量改表名 → 另存改好的副本或执行到当前库。

- **加脚本**：把 `.sql` 拖进那一页的虚线框，或点一下虚线框选文件（可多选）。
  自动统计脚本中所有 `CREATE TABLE [IF NOT EXISTS] \`表名\`` 语句并提取表名
  （兼容反引号/裸名/schema 限定名，按首次出现顺序展示；INSERT INTO 等其他语句不计入）。
  入口与「Excel 导入」那页完全一样，这一页不再有单独的「添加 SQL 文件」按钮；
  拖进来的东西混着不是 `.sql` 的会逐个点名跳过，整批都不是时明说一句已忽略
- **清空待上传文件**排在表格下面那一排的最左，与第一页同名按钮同一位置同一语义：
  把清单里的脚本整份清掉，磁盘上的脚本不动
- **添加结果弹窗逐个列出完整路径**：每个成功读入的脚本一行（带表数），已在列表的重复项
  与读不进来的文件也按完整路径点名并写明原因；同名脚本放在不同目录时，靠这一列才分得清
  刚才加进来的是哪一份
- **两个前缀按钮只改页面显示**：「当前表名」列和双击打开的元数据标题同步变，
  脚本正文一个字不动，也不弹进度框；点保存、执行或两颗生成按钮时才真正写进脚本。
  前缀框清空后再点任一前缀按钮，显示恢复为脚本原名
- **批量应用前缀**：给页面显示名加一段；已带该前缀的表自动跳过，重复应用不会叠加
- **替换首个前缀**：同一个输入框，基于页面当前显示名把**第一个下划线之前那段**
  换成填入的内容（先加过显示前缀就接着换：`ods_t_order` → `change_t_order`、
  `adb_table2` → `change_table2`）；表名里没有下划线（`users`）或以下划线开头（`_tmp`）的
  **不改**并在日志说明；末尾下划线不用写（`change` 与 `change_` 等价）；
  已是该首段的重复点不叠加；只允许字母/数字/下划线，其他字符弹窗拒绝，不会生成非法表名
- 两个按钮的分工：**加一段**用前者，**换掉已有的第一段**用后者；
  换完的显示名如果再应用前缀，会基于它计算（`dim_change_t_order`）
- **保存修改后ddl脚本**：先把显示名写进内存脚本（带反引号的引用以及语句头裸名一并同步改写），
  再另存为 `原名_prefix.sql`，不覆盖原文件；没有可保存的改动时也会弹窗说明；
  结果弹窗逐个列出写出的副本完整路径，写失败的按源文件路径点名原因
- **执行修改后ddl脚本到当前库**：点击时先把显示名写进脚本，再按上方公共连接区选定的目标库执行；**每个文件一个事务**——
  先开启事务，逐条执行，任一语句失败立即回滚整个事务并在日志报错（后续语句不再执行），
  全部成功才提交；注意 MySQL 的 CREATE/DROP/ALTER 等 DDL 会隐式提交，无法随事务回滚；
  语句切分能正确跳过字符串/反引号/注释中的分号；不支持含 DELIMITER 的存储过程脚本；
  文件编码按 UTF-8（含 BOM）→ GBK 依次尝试，dump 里夹二进制字段时按 UTF-8 替换坏字节，
  中文表名、表注释与字段注释不会变成乱码；执行结果弹窗先写成功/失败文件数，再列目标库与每个脚本的
  完整路径、结局（成功/失败/跳过/已取消）及失败位置
- **覆盖已存在表（先 DROP 再建）**：底部操作条最左边那颗勾选框，**默认不勾选**。勾上后只在
   **执行副本**的最前面按建表目标的出现顺序倒着补一段 `DROP TABLE IF EXISTS`（近似先删子表再删父表），
   DROP 完空一行再接原脚本；脚本正文、保存出来的副本与两份生成件都不受影响。
   只认整句以 `CREATE TABLE` 开头的语句——注释里写的建表、字符串里的建表都不删，这是删除动作，
   判据比"清单里显示哪些表"更严；schema 限定名（`db.tbl`）整段保留，删的就是那个库里的表；
   同一个目标在脚本里出现多次只删一次，日志 `[覆盖]` 那一行逐一点名删了哪些表
- **生成标准excel文件 / 生成简易excel文件**：排在「执行修改后ddl脚本到当前库」右侧，与「Excel 导入」页
  那两颗同名按钮产物形状完全一致（程序同级建 `sql_meta_data_file_年月日` /
  `sql_simple_meta_data_file_年月日` 目录，一张表一个 xlsx；目录名带 `sql_` 前缀，
  与「Excel 导入」页的生成件互不覆盖、也无需互等），区别只在数据源——这里只看脚本正文里的
  `CREATE TABLE` 列定义，不连库、也不看 `INSERT`
  - 取的是**改名之后的当前正文**，所以"先批量改前缀、再生成交付件"这条路是通的，
    产物里的表名就是新表名
  - 脚本里只有结构没有数据，「数据」Sheet 只剩英文字段名那一行表头，给下游当可填模板
  - 元数据 Sheet 只能装「一个类型关键字 + 纯数字长度」，`UNSIGNED` / `ZEROFILL` /
    `CHARACTER SET` / `COLLATE` 会被丢掉，`ENUM('a','b')` 这类括号里不是数字的按 `TEXT` 导出；
    每一处都在日志里逐列点名（`! [WARN] 说明 | ...`），不静默改语义
  - 同名表被定义多次只按**第一处**导出；`CREATE TABLE x LIKE y` 与 `... AS SELECT`
    里没有列定义，日志点名后跳过
- **第二页的清单列**：从左到右是 序号 / 文件 / 原表名 / 当前表名 / 表注释。原先有一列
  「CREATE 出现次数」，现场清单一律是 1（一张表在同一份脚本里被写两遍属少见情况，且日志
  已逐条点名），占着宽度只让人以为坏了，已去掉；换成表注释，取脚本里 `CREATE TABLE ...
  COMMENT='…'` 那句，与第一页的「表注释」同一含义，脚本里没写就留空
- **双击表格行**：双击「文件 / 原表名」任一列，会打开该表从 `CREATE TABLE`
  解析出的元数据，逐列查看字段名、注释、类型、长度、主键和可空；双击「当前表名」或
  「表注释」则进入单元格编辑。
  改表名同步改写脚本里的 CREATE / DROP / INSERT / ALTER / TRUNCATE 引用；
  改表注释写进那句 `CREATE TABLE` 的表选项 `COMMENT='…'`——原本没写就在列定义右括号后补一句，
  注释里的单引号按 MySQL 口径翻倍（读回来是原话），清空写成 `COMMENT=''`，
  `LIKE` / `AS SELECT` 不带表选项、改不动会当场说明原因。
  两者都只改内存里的脚本正文，点「保存修改后ddl脚本」才落副本；清单、元数据弹窗、
  DDL 预览与两份生成件立刻跟着变（标准件文件名就是「表注释（表名）.xlsx」）。
  字段定义在**读入脚本那一刻就按表解析好并缓存**，几十万行的脚本双击立刻弹出（实测 10.9MB /
  32612 行 / 124 张表：整份重解析 1.8 秒 → 只取一张 0 毫秒），改过表名后缓存按新名重挂；
  改成与另一张表同名时两行并成一行，缓存与生成都按「同名表只取第一处」那条既有规则走
- 这一页只保留「表名与字段名转大写」开关，**默认不勾选**。勾选后当前表名清单、表元数据和两份
  生成件一起按大写显示；脚本正文本身不回写。已删除「表名与字段名取拼音首字母」开关
- 两份 Excel 生成完成后，结果弹窗至少 820×420，正文可用鼠标选中并 Ctrl+C 复制
- Excel 导入同样是事务语义：每张表先开启事务，数据插入成功后提交，失败整体回滚并记录日志

## SQL 执行器页（第三个 Tab）

这一页有两种用法，共用一个结果区：手上有一份或一整套 `.sql` 脚本要按顺序打进库时，把文件拖进
脚本清单点「执行脚本文件」；只想临时问一句、顺手改点结构时，把 SQL 敲在编辑区点「执行编辑区 SQL」。
两路都打到上方公共连接区选定的库，输出都写进右侧「执行结果」区。文件这一路借「Excel 导入」页的
拖拽区与清单表、「SQL 脚本改名」页的底部动作条（覆盖开关在左、主按钮在右）；两路共用同一个
结果区，所以同一页同时只跑一个任务（互斥判据见"被挡下时"那条）。

- **页顶的目标库指向条**：与最上方那条连接状态栏同一次刷新，绿色写
  `目标库：库名 —— 编辑区 SQL 与脚本文件都执行到这个库`；没选库时整条隐藏，
  未选库的告警只由顶部状态栏说一次；
  主机和端口不在这条里（收在状态栏的悬停提示），这一页点的每条语句、每个脚本都落在这个库里
- **两种用法常驻一句**：页顶第二行写
  `两种用法：把 .sql 脚本拖到下面清单里按顺序执行；或直接在编辑区写 SQL 临时执行（多条用分号分隔）`，
  不必翻手册就知道这一页也能吃文件
- **脚本拖拽区与清单**：与「Excel 导入」页同一形状——虚线区可点击多选，也可以直接拖入；
  只收 `.sql`，混着别的文件时日志点名 `[跳过] 不是 SQL 脚本，未读入：说明.txt`，
  一个 `.sql` 都没有时写 `[提示] 拖入的不是 SQL 脚本文件，已忽略。`
- **清单四列**：序号 / 文件 / 大小 / 状态，只读、带斑马纹，文件名单元格悬停显示完整路径；
  大小按 B / KB / MB / GB 折算一位小数
- **加入即回执**：加入后弹「添加结果」，正文逐条给 `[已加入] 完整路径`、
  `[跳过] …：已在列表`、`[未加入] …：<读盘失败原因>`，日志同步写一行
  `===== 添加完成：N 个脚本，M 个无法访问，K 个重复 =====`；重复拖同一份不会进第二行，
  读不到的脚本（路径失效、权限不足）不会静默消失，弹窗用警告级
- **登记只记路径与大小**：正文等轮到它执行时才读盘，导入一份大 dump 不必先把所有文件读进内存
- **清空待执行脚本**：与第一页「清空待上传文件」同一位置同一语义，整份清出清单、磁盘上的脚本
  一个字节不动；清单空着时点它写 `[清空] 清单里没有脚本文件，无需清空`
- **底部动作条**：左边 `覆盖已存在表（先 DROP 再建）`，右边次要按钮 `执行编辑区 SQL`、
  主按钮 `执行脚本文件`；清单空着或有任务占着执行器时，主按钮灰着
- **按清单顺序执行，每个文件单独连接**：执行期间清单状态逐行刷新为 成功 / 失败 / 跳过 / 已取消
  （分色显示）。执行方式按文件自己定：手写脚本一个文件一个事务，全部语句成功才提交，
  中途出错本文件回滚、报出第几条出错语句与"前面 N 条已随事务回滚"，然后继续下一个文件；
  整库 dump 自动识别后走另一条通道（见下一条）
- **整库 dump 自动识别**：按开头或结尾的导出标记认出来（`-- MySQL dump`、`-- MariaDB dump`、
  `-- MySQL Shell dump`、`-- phpMyAdmin SQL Dump`，或结尾的 `-- Dump completed`），
  改为**不开事务、逐条提交、出错继续**——dump 里的 `CREATE/DROP/ALTER` 与 `LOCK TABLES`
  本来就会隐式提交，"整文件回滚"在那里兑现不了。识别到先写一行
  `[dump] 文件名：识别为整库 dump，按 dump 方式执行（不开启事务，逐条提交；出错继续，最后汇总）`。
  dump 里认 `DELIMITER` 指令，触发器 / 存储过程的整句不会被函数体里的分号切碎；
  `/*!40101 SET … */` 这类版本注释语句照常发给服务端。只有识别成 dump 的文件才这样切句，
  手写脚本与编辑区仍按分号切
- **dump 的建库与切库照常执行**：`CREATE DATABASE` 与 `USE` 是 dump 在说"这批表建在哪个库里"，
  跳过它们等于把用户要导的那个库抹掉、表反而散进界面随手选中的库。切库后日志写
  `[切库] 文件名：目标库换成 demo`，报错行与收尾都按切后的库说，
  收尾写 `[提交] 文件名：N 条语句已提交，目标库 demo，跳过 M 条删库语句`；
  界面选中的库与库列表不受影响，仍按上方连接区走。
  只有 `DROP DATABASE`（含 `/*!40000 DROP DATABASE … */` 写法）不执行，每跳一条日志写
  `[跳过] 文件名 第 i/n 条：DROP DATABASE（删库语句不执行）`——执行一次就把整个库删掉，
  这个风险与建库、切库不对等。
  有语句报错时继续执行后面的语句，清单写
  `已执行 4/7 条，1 条语句报错（逐条提交，已成功的已落库）`，
  日志逐条给出错语句与原因（最多详细列 20 条，超出只报还有几条）；连接断开时剩余语句不再执行
- **只写注释的文件不算执行过**：切句后剔掉没有可执行内容的片段，整份只剩注释的脚本记
  `[跳过] …：没有可执行的语句`，不占连接、也不推进度条
- **取消与断连**：手写脚本取消后回滚当前文件；dump 通道已逐条提交的语句留在库里，
  清单写 `已执行 46/121 条（逐条提交，已执行的已落库）`，两路都把剩余文件标
  「已取消：未执行」；连不上目标库时立刻停手，日志写清目标库、用户与原因，
  剩余脚本都不执行（不再补一条汇总弹窗，同一件事不说两遍）
- **执行完成回执**：日志一行 `===== 执行完成：成功 N 个文件，失败 M 个文件 =====`，
  弹窗正文逐文件给 `[成功] / [失败] / [跳过] / [已取消] 完整路径：结局`，并写目标库与
  「详见日志。」；有失败时弹窗用警告级
- **覆盖已存在表**：只对「执行脚本文件」生效。勾选后给每个文件补一份**执行副本**，在开头按
  建表顺序倒序补 `DROP TABLE IF EXISTS`（近似"先删子表再删父表"），只认整句以
  `CREATE TABLE` 开头的语句，注释或字符串里出现的建表不会触发删除；磁盘上的脚本正文不动，
  日志逐文件点名 `[覆盖] …：执行前先 DROP …`，没有一个建表目标时写
  `[覆盖] 脚本里没有以 CREATE TABLE 开头的语句，没有表需要先删除`。默认不勾选
- **示例 (?)**：打开 100 条 MySQL 示例清单，分 12 组（建库与选库 4 条、建表与改表 11 条、
  元数据与治理体检 10 条、数据质量检查 20 条、数据标准化与清洗 12 条、主数据与重复数据 8 条、
  数据血缘与影响分析 7 条、安全与权限治理 6 条、生命周期与归档 6 条、性能与容量治理 7 条、
  查询与执行计划 4 条、数据修正 5 条），其中数据治理主题占 76 条。左边选中一条，右边给语句全文，
  「复制到剪贴板」或「插入到编辑区」两种出口；对话框不锁界面，可以边看边改
- 示例的唯一来源是根目录 `sql_samples.py`，Java 侧由 `java/tools/export_sql_samples.py`
  导出成 `SqlSamples.java`——两边各写一份必然各说各话
- **执行**：按分号切句逐条执行，结果区逐条给 `第 i/n 条：<语句>`、`影响 N 行` 或结果集；
  **全部成功才提交，中途出错整批回滚**，失败那句标红并附 DDL 隐式提交的提醒
- 查询出来的结果**排成等宽表格**再写进结果区：列名一行、上下与表头下面各一条分隔线，
  每列按显示宽度补齐（汉字占两列），中英混排也对得齐；空格子写 `NULL`，
  取值里的换行与制表符写成可见转义 `\n` / `\t`，单格超过 40 列截断补省略号
- 查询结果最多打印前 200 行，超出只报总行数，几十万行不会刷爆结果区；
  结果区与编辑区同一支等宽字体
- **清空编辑区 / 清空结果区**：两颗分别放在「SQL 文本」与「执行结果」两栏的头一行，
  各管自己那一边——清结果区不会带走敲了一半的语句，清编辑区不会抹掉上次的结果
- 编辑区不折行（一句 SQL 一行看到底），开场预置 `SELECT 1 AS 连通检查;`
- 切句用的是与「SQL 脚本改名」页同一个 `split_sql_statements`，
  字符串/反引号/注释里的分号同样不会误切；在此之上执行器再剔掉"整句只剩注释"的片段
  （`has_executable_content`）——否则会出现切出来一条、界面上说"已提交 1 条"，
  而那句其实什么都没做
- 一批之内**不做逐句提交**：中途失败时前面已执行的 DML 能整批回滚，
  与「执行」按钮 tooltip 说的"全部成功才提交"对齐
- 这一页执行的就是提交的语句本身，`DROP` / `TRUNCATE` 不另设确认弹窗——
  删东西前先在结果区核对那句是不是自己要执行的
- 示例集带 `check_sql_samples.py`，可逐条打到真库上验证可执行（需要先起 MySQL；
  互相依赖的示例如"改名后再 `SHOW CREATE TABLE`"按 `PREREQ` 表先建前置）；
  没连库时不算验证通过，脚本会逐条报出失败项与错误原因
- 两份执行器本体（`core/sql_execute.py` 与 Java `core/SqlExecute.java`）用同四段输入
  打到同一个真库上跑，发出的每一行逐行比对、落库行数各自回查
  （`check_sql_exec_parity.py`，Java 侧探针是 `java/verify/.../SqlExecCli.java`；
  口令只走 `PT_USER`/`PT_PASS`/`PT_DB` 环境变量，未设时该脚本显式跳过并说明原因）

## 日志与报错展示

三个页签各有一个独立日志区（`Excel 导入` 页底部、`SQL 脚本改名` 页底部、
`SQL 执行器` 页右半边的结果区），互不串台，
各自保留最近 2000 条记录，超出后自动丢弃最早的，不会无限吃内存。
三个日志区都有最小高度（`LOG_MIN_LINES = 4` 行，按各自字体量出来换算成像素）：
没有这个下限时，三段分栏按比例一缩，默认窗口里日志实测只剩两行，往上滚就看不到上一条。
按行数而不是按像素约定，是因为同一档字号在 Qt 与 Swing 里量出来的行高本就不同，
写同一个像素数会变成"两边都满足同一个数、实际看到的行数不一样"。
下限也不能给多——主窗口自身最小高就有 717px，按 8 行给会顶到 847px，
1024x768 的现场机与"整窗落在屏幕可用区内"那条断言都撑不住。
两个三段分栏页的默认分配：拖拽区按窗口高的 110/670 给，表格拿走其余高度，
日志段**正好压在自己的最小高度上**（四行）。表格是主工作面，默认窗口里能多看几行；
日志只留一行标题加四行记录的位置，往上滚仍然看得到前几条。
第三个页签（`SQL 执行器`）同样按 110/670 摆拖拽区，脚本清单拿其余高度，
末段「编辑区与结果」压在自己的最小高度上（编辑区四行）——空清单的图标与引导语才看得全。
这个"压到最小"只在用户亲手拖过把手之前成立：程序在窗口每次 Resize 时都按绝对高度重摆一次
（Qt 的 `QSplitter` 会在尺寸总和不等于可用高度时再分一次，只在构造时摆会留下最后一轮
拉伸分给日志的几十像素；Swing 的 `JSplitPane` 同一毛病，用 `ComponentListener` 每轮重摆），
一旦检测到用户拖动分隔条（Qt `splitterMoved`、Swing 给 Divider 挂 MouseListener），
日志高度就归用户，程序不再抢，之后窗口怎么缩放都保持用户自己拉的比例。
旧默认（Excel 110 : 200 : 330、SQL 110 : 230 : 330）下默认窗口里文件表视口实测只剩 37px，
不到两行；现在日志压到四行下限，表格拿回剩下的高度，视口足够看十几行。

每条记录写成 `[年-月-日 时:分:秒] 符号 [级别] 正文`，四档级别与命令行版同一套标签，时间戳也跟命令行日志文件同一形状：

| 级别 | 行首 | 颜色 | 用在什么场合 |
| --- | --- | --- | --- |
| OK | `+ [OK]` | 绿色 | 这件事做成了：解析、加载、保存、提交、改名 |
| INFO | `- [INFO]` | 默认色 | 记一笔，不需要处理：开关切换、移除文件、清理临时目录 |
| WARN | `! [WARN]` | 琥珀加粗 | 这次没做成但有原因：跳过、重复、取消、空包、被拦下的点击 |
| ERROR | `x [ERROR]` | 红色加粗 | 失败，需要处理：解析失败、建表失败、连不上库、任务异常 |

级别由正文行首的中文标签定（`core/log_text.py` 的 `LOG_TAG_LEVEL`，Java 侧
`core/LogText.java` 同名表逐条对齐），调用方给的 `error=True` 优先。
颜色与级别都由这一处决定，所以三个页签的日志框不会出现"这一页有时间戳、那一页没有"。
上色写进控件的字符格式（`append_log()` 用 `QTextCursor.mergeCharFormat` 覆盖本条记录的所有块，
Swing 侧是 `LogPanel.render()` 按级别加 `StyleConstants`），复制日志时文本内容不受影响。

正文里并列的事实用 `|` 分段，补充说明缩进挂在下一行：

```
[2026-10-23 14:05:12] + [OK] [已解析] 水库基础信息.xlsx → 表名预置 dim_reservoir_info | 字段 18 列 | 数据 5 行 | 主键 `BH`（整数类型，全列非空且唯一）
    说明 | 整列为空的字段照旧保留：备注
[2026-10-23 14:05:20] ! [WARN] [跳过] 已在列表：人员信息表.xlsx
```

时间戳只打在每条记录的第一行；本来就有缩进的续行（结果表格、驱动原文）属于上一条记录，
给它们逐个打时间戳会把等宽表格顶歪。

报错不再只打 `str(e)`（pymysql 的异常会打成 `(1064, '...')` 这种元组，错误码和正文混在一起），
而是由 `describe_db_error()` 展开为 **异常类型 + MySQL 错误码 + 服务端原始报错全文**。
一条典型的 SQL 执行失败长这样：

```
[2026-10-23 14:07:02] x [ERROR] [执行失败] a.sql 第 2/3 条语句报错，目标库 testdb@127.0.0.1:3306，本文件事务已回滚
    ProgrammingError（MySQL 错误码 1064）：You have an error in your SQL syntax; ...
    出错语句：
        INSERT INTO t_bad VALUE (1)
    前面 1 条语句已随事务回滚。注意：CREATE/DROP/ALTER 等 DDL 在 MySQL 中隐式提交，不会随事务回滚；回滚仅对其后的数据操作生效。
```

各场景的详细内容口径：

| 场景 | 日志里给出的信息 |
| --- | --- |
| SQL 脚本执行失败 | 文件名、第几条 / 共几条、目标库 `库名@主机:端口`、错误码与原始报错、**出错语句全文**、已回滚条数与 DDL 隐式提交提示 |
| SQL 脚本连接失败 | `库名@主机:端口`、用户名、错误码与原始报错，并注明"剩余脚本均未执行" |
| SQL 文件读取失败 | 文件名、异常类型与原因，并注明该文件已跳过 |
| Excel 建表失败 | 表名、目标库、错误码与原始报错、**失败的完整建表 DDL** |
| Excel 导入失败 | 表名、目标库、已尝试写入的数据行数、错误码与原始报错、回滚说明 |
| 加载库列表失败 | `主机:端口`、用户名、错误码与原始报错 |
| Excel 解析失败 | 文件路径、异常类型与原因，并注明该文件已跳过 |
| 结尾汇总行 | `===== 执行完成：成功 X 个文件，失败 Y 个文件 =====` / `全部完成：成功 X 张表，失败 Y 张表`，**只要 Y>0 整行按错误级标红** |

出错语句全文默认完整展示，超过 2000 字符会截断并标注 `原文共 N 字符`，
避免一条巨大的批量 `INSERT` 把日志刷满。

## ZIP 压缩包导入

拖入或选中 `.zip` 后，包内的 Excel 会被展开成一条条普通的待导入记录，
之后的表名/字段编辑、结构预览、导入、失败重试流程与直接拖文件完全一致。

展开规则（实现在 `core/zip_import.py`）：

- **递归子目录**：`北京/河道水文站.xlsx` 这类包内嵌套目录里的文件同样收，
  解压时保留包内目录结构，所以 `北京/水库.xlsx` 与 `河北/水库.xlsx` 不会互相覆盖，
  两张表的表名交由去重逻辑给出 `shui_ku` / `shui_ku_2`
- **不递归嵌套 zip**：包里的 `.zip` 一律跳过（日志会报"跳过 N 个嵌套 zip"），
  需要导入就把内层包单独拖进来
- **非 Excel 文件忽略并计数**：`.txt` / `.csv` 等不进列表，日志汇总忽略了几个
- **Excel 临时锁文件忽略**：`~$xxx.xlsx` 这类 Office 打开文件时留下的锁文件不是合法工作簿，直接跳过
- **中文文件名按 GBK 兜底解码**：Windows 自带"发送到压缩文件夹"存中文条目名用的是 GBK 且
  不打 UTF-8 标记，标准库会按 cp437 解成乱码，那样表名和表注释会全废。
  `decode_name()` 依据通用位标记 bit11 判断：带标记直接用，不带则 `cp437 → gbk` 回退解码。
  **只在名字确实能原样往返 cp437 时才折回**：汉字本来就不在 cp437 的取值范围里，
  硬折会把每个字变成一个问号，落点随即被 Windows 判成「文件名、目录名或卷标语法不正确」。
  Java 线尤其需要这条——`String.getBytes(CP437)` 不像 Python 那样抛异常，它是静默替换；
  而 JDK 8 的 `ZipFile` 默认按 UTF-8 **严格**解条目名，GBK 命名的包连枚举第一条都会抛
  `IllegalArgumentException: MALFORMED`，所以 Java 侧打开压缩包时显式指定 GBK
  （带 UTF-8 标记的条目仍按 UTF-8 解，两种包都对，见 `core/ZipImport.java::open`）
- **ZIP64 的包照解**：条目数超 65535 或中央目录超 4GB 时，这三个数改写在 64 位的
  ZIP64 EOCD 里，旧的 16/32 位 EOCD 只剩 `0xFFFF` / `0xFFFFFFFF` 占位。
  Java 线要自己扫中央目录拿位标记（JDK 的 `ZipEntry` 不暴露通用位标记），
  扫描器必须一并读 ZIP64 EOCD 与它的定位块，否则位标记整份失明
- **加密包给中文话**：JDK 在打开阶段就整包拒绝带 bit0 的压缩包，回的是英文那句
  `invalid CEN header (encrypted entry)`；Java 线先按自己扫到的 bit0 报
  「压缩包已加密（哪一条），请先解密后再导入」，与 Python 线同一句
- **解压落点按"会话内已解出的文件数"编号**：包名同名（不同目录下的两个 `B.zip`）时，
  目录号也必须一路向前。按批次 +1 而批内按已解文件数跳号的写法过几批就会拐回用过的号，
  把前一批解出来的文件原地覆盖，同名文件还会被判成「已在待导入列表」而静默少一张表
- **防 zip slip**：包内出现 `../` 或绝对路径的条目会被剥掉越界部分再解压，不会写到目标目录之外
- **加密 / 损坏 / 空包**分别给出明确报错，整条标红；单个包失败只跳过该包，不影响同批其他文件

日志示例：

```
[2026-10-23 14:05:12] - [INFO] [压缩包] 数据打包.zip：展开 12 个 Excel，忽略 3 个非 Excel 文件，跳过 1 个嵌套 zip（不支持递归展开）
[2026-10-23 14:05:12] + [OK] [已解析] 水库基础信息.xlsx → 表名预置 shui_ku_ji_chu_xin_xi | 字段 5 列 | 数据 81 行 | 主键 `bian_hao`（...）
[2026-10-23 14:05:13] x [ERROR] [压缩包为空] 报告.zip：包内没有找到 .xlsx / .xls 文件
```

「文件」列显示包内文件名，鼠标悬停的 tooltip 会标出完整来源，形如
`数据打包.zip!北京/水库基础信息.xlsx`，便于确认某个表是从包里哪个位置来的。

展开出的文件放在系统临时目录 `%TEMP%\e2m_gui_*`，关闭窗口时自动清理。
所以**关掉程序后**来自 ZIP 的失败文件不能直接重试，要重新拖一次压缩包。

## 表格标识（每张表左上角一句）

界面上每张表格左上角都写着一句标识，标题里顺带说明这一张表怎么操作——
第一页那句「待导入文件（…）」是最早的样子，其余几处照它补齐：

| 位置 | 标题 |
| --- | --- |
| 第一页主表格 | 待导入文件（单击表名改名，双击其他列改字段） |
| 第二页主表格 | 待处理的脚本表（双击表名或表注释编辑，双击其他列看元数据） |
| 第二页双击一行打开的元数据弹窗 | 字段清单（共 N 列） |

- 元数据弹窗那句带列数，省得滚到表格末尾数这一张表解析出了多少列；`LIKE` / `AS SELECT`
  那种没有列定义的写法压根开不出这个弹窗（日志会点名"未找到表 X 的定义"），所以不会出现「共 0 列」
- 结构预览弹窗（第一页双击一行打开的那个）**不重复加**：那一页每个 tab 上写的就是表名，
  已经贴在表格正上方，再加一层标题是把同一件事说两遍
- 字号两栈同一组数：**表格内容与表头 11 号、日志 10 号**（与 Excel 数据网格同级，
  内容比日志大一档——这一页真正要读的是表格里的字段名，日志只是过程回执）；
  行高按字体量出来，不写死像素。
  这两档由对撞键 `font.table.pt` / `font.log.pt` 跨线核同值，各线自己再断一次"表格 > 日志"
- 第三页「SQL 执行器」的 SQL 文本与执行结果也用**日志那一档（10 号）**：与第一页日志一样大，
  同源到日志常量（Python `LOG_FONT_SIZE` / Java `LogPanel.DEFAULT_FONT_SIZE`），不单独占一档；
  字族仍是等宽体，结果区靠它对齐
- 实现上就是套一层带标题的容器（Qt 的 `QGroupBox`、Swing 的 `TitledBorder`），
  两条线同一句文案；对撞器比的是从**真控件上读回来的标题**（`table.file.title` / `table.sql.title`），
  不是两边各抄一份常量——抄来的那份改了，另一份不会红

## 添加结果弹窗

无论点虚线区选文件还是直接拖拽，添加完成后都会**把汇总同时打进日志区并弹窗**——
日志可回溯、弹窗防走神漏看，两处说的是同一句话：弹窗那份不带行首标记，
日志这一条多了 `[添加结果]` 标签与时间戳/级别前缀，续行缩进 4 格挂在同一条记录下面。
散文件与压缩包各占一行，只输出本次实际用到的行：

```
[2026-10-23 14:05:12] - [INFO] [压缩包] 数据打包.zip：展开 12 个 Excel，忽略 3 个非 Excel 文件
[2026-10-23 14:05:12] + [OK] [已解析] 人员信息表.xlsx → 表名预置 ren_yuan_xin_xi_biao | 字段 8 列 | 数据 5 行 | 主键 ...
[2026-10-23 14:05:12] + [OK] [已解析] 人员信息表（t_user）.xlsx → 表名预置 t_user | 字段 8 列 | 数据 5 行 | 主键 ...
[2026-10-23 14:05:12] ! [WARN] [添加结果] 添加 3 项文件，包含 2 项 xlsx 文件、1 项 xls 文件
    添加 1 项 zip 文件，包含 12 项 xlsx 文件、0 项 xls 文件
    另有 2 项解析失败、1 项重复已跳过，详见日志
```

`[添加结果]` 这一条在真有"另有 …"时按告警级上色，全部成功时是成功级——绿色那行就说明
这一批一个都没被拒。

口径说明：

- **xlsx / xls 的数量只统计真正进入待导入列表的**，解析失败和重复跳过的不计入，
  所以弹窗上的数字和列表里的行数始终对得上
- 「添加 N 项 zip 文件」的 N 指你投入了几个包（压缩包本身不进列表，只是被展开）
- **第三行只在真有异常时出现**，四类异常按 `、` 拼接，为 0 的不写：
  `N 项含合并单元格已拒绝`、`N 项解析失败`、`N 项重复已跳过`、
  `N 个压缩包无法展开`、`N 个压缩包内没有 Excel`
- 全部成功时只有前两行，不会出现「另有」
- 只拖了空压缩包（包内没有 Excel）时**也会弹窗**，否则界面看着像没反应
- 完全没有任何输入时不弹空窗
- 失败的具体原因（错误码、出错语句）始终在日志里标红，汇总只报数量不塞细节
- 汇总行始终出现在逐条 `[已解析]` / `[解析失败]` **之后**，便于顺着往下看

**重复文件在日志里也有对应行**（`[重复跳过] xxx.xlsx 已在待导入列表`），
便于核对弹窗上的数字。此前重复文件是被静默跳过的，日志里查不到任何痕迹。

## 合并表头与合并单元格

### 顶部两行表头：自动压成一行

原始表常见这种形状：第一行是分组名（`技术公司` 横跨 4 列），第二行是子项
（`小计 / 高层 / 中层 / 普通员工`），左侧字段（`序号`、`单位名称`…）纵向合并两行。
导入时按列把上下两行拼成「父-子」表头，再照常推断类型、选主键：

| 原始表头 | 展开后的表头 |
| --- | --- |
| 第一行 `技术公司` 横跨 4 列，第二行 `小计 / 高层 / 中层 / 普通员工` | `技术公司-小计`、`技术公司-高层`、`技术公司-中层`、`技术公司-普通员工` |
| 第一行 `序号` 纵向合并两行，第二行没有字 | `序号`（只留一份，不会变成 `序号-序号`） |

展开后仍走原来的表头规则：空表头按列宽兜底为 `col`、`col_2`…，重名追加 `.1`、`.2`，
字段名由「父-子」整串转拼音。日志会在 `[已解析]` 行说明表头是几行压出来的：

```
[2026-10-23 14:05:12] + [OK] [已解析] 原始表.xlsx → 表名预置 yuan_shi_biao | 字段 17 列 | 数据 3 行 | 合并表头按 2 行展开 | 主键 `xu_hao`（…）
```

只认工作簿 1 这种**标准两行表头**，必须同时满足四条
（`core/merge_check.py` 的 `header_merge_plan`）：

1. 只有第一个 Sheet 有合并区（第二个 Sheet 有合并区，整个文件仍拒绝）
2. 每一处合并区都从第 1 行开始
3. 合并区只能是两种：跨两行的单列纵向合并（`A1:A2`），或只横跨第 1 行的多列合并（`J1:M1`）
4. 至少一处跨两行（表头深度因此固定为 2）

### 其余合并单元格：直接拒绝导入

不满足上述任一条的文件**一律不导入**，也不进入「待导入文件」列表。原因是合并区只有左上角那一格有值，
其余格被 pandas 读进来是空值——数据行被合并会静默丢值，表头形状对不上时字段名与列会错位。
与其导出一份错数据，不如挡在门外让人去改源文件。拒绝只针对该文件，不会中断整批，
同批其他文件照常解析。

| 情形 | 行为 |
| --- | --- |
| 数据行里有合并区 | 整个文件拒绝 |
| 第二个及以后的 Sheet 有合并区 | 整个文件拒绝 |
| 只有一个 Sheet、且合并区只在单行表头里（表头深度 = 1） | 整个文件拒绝 |
| 表头块之外的合并区（含跨出表头块、伸进数据行） | 整个文件拒绝 |
| 三行表头（如 `A1:A3`） | 整个文件拒绝 |
| 第 2 行里的子合并（如 `B2:C2`） | 整个文件拒绝 |
| 2x2 合并块（如 `B1:C2`） | 整个文件拒绝 |
| ZIP 压缩包里的某个 Excel 被拒 | 只拒绝那一个文件，同包内其他干净文件正常导入 |

日志逐条标红，并给出具体位置便于回源文件修改：

```
[合并单元格] 两页都合并.xlsx 含 3 处合并区，已拒绝导入，未进入待导入列表
    检测到合并单元格：「字段定义」1 处（A1:G1）；「数据」2 处（A1:B1、A2:B2）
    原因：合并区只有左上角有值，其余格读进来是空值，字段名与数据会错位。请先在 Excel 中取消合并后重新添加。
```

添加结果汇总里单列一类（顺序排在"解析失败"之前）：

```
添加 1 项文件，包含 1 项 xlsx 文件、0 项 xls 文件
另有 3 项含合并单元格已拒绝，详见日志
```

实现要点（`core/merge_check.py` 与 `core/infer.py` 的 `_flatten_merged_header`）：

- **在 `pd.read_excel` 之前判**，被拒的文件不用付读数据的代价。实测 20 万行的表：
  流式扫描 116 ms，而 `openpyxl` 全量加载要 8.7 秒、`pd.read_excel` 要 6.4 秒
- `.xlsx` 用流式扫描 sheet XML 里的 `<mergeCell>`，**不做"命中即停"**——
  无合并的文件本来就得扫到底才能确认，早停省不下时间，却会让"含 N 处合并区"的 N 恒等于 1，报出假数字
- sheet 名到 XML 部件的映射走 `workbook.xml` + `workbook.xml.rels` 的 `r:id` 关系，
  不能假定 `sheet1.xml` 就是第一个 Sheet；`Relationship` 标签的 `Id`/`Target` 属性顺序
  在不同生成器下不一样，必须逐个属性取
- 合并区按左上角坐标**行优先**排序输出（列名不能按字符串排，否则 `A10` 会跑到 `A2` 前面）
- `A1:A1` 这类只跨一格的伪合并不算合并区
- `.xls` 走 `xlrd`，且**必须 `formatting_info=True`** 才会填 `merged_cells`——
  默认参数下恒为空，会把满是合并区的真实表单（实测某份有 19 处）当成干净文件放过去
- 展开时先把每个合并区左上角的值铺满整个矩形（纵向合并因此只留一份标签，横向合并把组名铺到组内每列），
  再逐列把非空、且与上一行不同的标签用 `-` 连接；铺值和拼接都只在表头深度内进行
- Java 线同一套规则，金标准夹具 `两行合并表头（ods_t_merged_header）.xlsx` 带「原始表」与
  「结构化参考」两页，展开结果与参考页逐字比对

## 支持的 Excel 类型

1. **普通数据表**（单个数据 Sheet）：表名/注释来自文件名，字段从数据推断（见上方规则）；
   表头可以是单行，也可以是顶部两行合并表头（自动压成 `父-子` 一行，见上方「合并表头与合并单元格」）
2. **结构定义表**（元数据 Sheet + 数据 Sheet）：字段以定义为准，不再推断。
   任一 Sheet 的表头含「字段名、数据类型」及以下任一列即识别为元数据：
   `序号 | 字段名(英文) | 字段注释(中文) | 数据类型 | 长度 | 是否主键 | 是否可为空`
   - `长度` 填 `20` 或 `10,2`（→ DECIMAL(10,2)）；类型列也可直接写 `VARCHAR(50)`，
     中文括号/逗号均可识别；类型无长度时写 DATETIME/TEXT 等即可
   - `是否主键=是` → 主键（支持多字段组合）；`是否可为空=否` → NOT NULL，否则 DEFAULT NULL
   - 数据 Sheet 按字段名对齐（大小写不敏感）：多余列忽略并在日志提示，缺失列补 NULL；
     元数据 Sheet 位置不限（自动识别），只有定义没有数据时建空表
   - 字段名/类型仍可在「表结构预览」中修改，主键可重新勾选

## 说明

- **文件名规则**：文件名（去扩展名）以「`（表名）`」结尾、且括号内为**纯英文**（字母/数字/下划线）时，
  括号内英文作表名、括号前中文作表注释；中英文括号均可，如
  `北京市水务局-水库基础信息（dim_reservoir_info）.xlsx` →
  表名 `dim_reservoir_info`、注释 `北京市水务局-水库基础信息`
- 括号内容**必须是能直接当表名用的英文标识符**（以字母或下划线开头、只含字母/数字/下划线、
  至少含一个字母）才采用，并统一转小写；否则一律回退：
  - 括号内是中文 → `人员信息表（人事处人员）.xlsx` →
    `ren_yuan_xin_xi_biao_ren_shi_chu_ren_yuan`（**括号内外的中文一起转拼音**，绝不产出汉字表名）
  - 括号内是纯数字序号 → `人员信息表（7）.xlsx` → `ren_yuan_xin_xi_biao_7`
    （绝不产出 `t_7` 这种只含数字的表名；`（2026）`同理）
  - 括号内是版本号 → `订单表（V2）.xlsx` → `ding_dan_biao_v2`（`v2`、`V2_1` 同理）。
    版本号不是表名，回退时版本段留在末尾做区分；勾首字母为 `ddbv2`，
    再勾转大写为 `DDBV2`。只认「单个 V + 数字」，`order2`、`A1` 这类仍直接采用
  - 括号内以数字开头（`7_dim`）、空括号、纯符号括号 → 同样回退
  - 回退时**表注释保留完整文件名**（含括号内容），所以
    `人员信息表（人事处）` 与 `人员信息表（财务部）` 得到两个不同且可辨识的表名，
    而不是同名加 `_2` 谁也看不出是谁
- 回退默认规则：**表名 = 文件名汉字转拼音**（每个音节用下划线分隔；
  小写字母/数字/下划线，不以数字开头，最长 64 字符）；
  **超长处理与下面的字段名规则完全一致**：全拼不超过 64 用全拼，超过则整名降级为各音节首字母
  （数字/英文音节整段保留），如
  `北京市海淀区水务局下属大型水库枢纽工程基础信息汇总表.xlsx` →
  `bjshdqswjxsdxsksngcjcxxhzb` —— 每个汉字都还在名字里，比"砍掉后半段"更能区分不同文件；
  表注释 = 文件名；同名文件重复添加会自动加序号
- **主键自动选择与修改**（主键约束至多一个，可由一个或多个字段组成组合主键）：
  添加文件时自动分析挑选（类型为 INT/BIGINT 或 ≤255 的 VARCHAR、全列非空唯一、
  注释/字段名带 ID/编号/代码 等语义，同分取更短者），无合适字段则不设主键；
  「生成表结构预览」中每行有主键勾选框，可自由勾选/取消一个或多个字段，
  保存时自动校验类型、非空与组合唯一，不通过会提示且不生效；只有表头的空表
  **不自动选主键**（没数据判不了唯一与非空），但可以手工勾选——空集天然满足
  非空与唯一，此时只校验字段类型
- **表名前缀**：批量应用到全部表名；新添加的文件自动带上当前前缀；
  换前缀重复应用不会叠加（基于基础表名重算）；留空并点「批量应用前缀」可移除前缀
- **字段命名规则**：中文表头逐音节转拼音、下划线连接成蛇形（`订单金额` → `ding_dan_jin_e`）；
  全拼不超过 **30 字符**就用全拼，超过则整列强制降级为各音节首字母且**不加下划线**
  （`北京市海淀区水务局下属大型水库枢纽工程基础信息汇总表` → `bjshdqswjxsdxsksngcjcxxhzb`，
  单字母之间加分隔符不增加可读性却把长度翻倍、白白挤掉后面的音节）。
  首字母仍超 30 时截断。纯英文表头原样蛇形化不做拼音转换（`station_code` 保持不变）；
  首字符为数字补 `f_` 前缀；重名自动加 `_2`、`_3`；产出保证是合法 MySQL 标识符。
  - **成对括号里的注释整段不进名字**（`_strip_header_annotations`，在 `_col_to_field` 里先剥再转写）：
    `发布日期（yyyy-MM-dd）` → `fa_bu_ri_qi`、`金额（元）` → `jin_e`、
    `是否已婚【是/否】` → `shi_fou_yi_hun`、`★（必填）联系电话` → `lian_xi_dian_hua`。
    括号按码位清单认（半角 `()`、全角 `（）`、`[]［］【】〔〕〖〗〈《「『{}｛` 各配对，
    两侧同一份清单）；嵌套最多剥三轮，配不对的孤立括号符最后删掉。
    **左括号没配右半边**时从它起整段丢（`发布日期（yyyy-MM-dd` → `fa_bu_ri_qi`），
    手写漏括号是表单里最常见的一种脏写法。
    **整格就是括号时不剥空**（`（备注说明）` → `bei_zhu_shuo_ming`），否则退化成 `col`。
    列注释仍是**原始表头**，口径信息不丢；表名那条不受影响（文件名的 `（英文表名）` 另有规则）
  - **日期时间格式掩码串即使不带括号也不进名字**（`_MASK_SEG_RE`）：
    `发布日期：yyyy-MM-dd` / `发布日期 yyyy-MM-dd` / `发布日期/yyyy/MM/dd` /
    `填表日期 yyyymmdd` 都只剩名字部分。判定只认"首段是 `[yYmMdDhHsS]{2,}`、
    两头不贴字母数字、后续段可以是纯数字"的串，所以有三条反向守卫钉着不许扩大：
    `1.0mm` 里的 `mm` 前有数字不被吃、纯英文表头（`station_code` / `MM-dd` / `qty`）
    整条不参与掩码判断、真日期 `2020-01-01` 这类首位是数字的串不是掩码
  - **表名与字段名共用同一套拼音切分与超长降级逻辑**（`core/infer.py` 的 `_syllables`
    加 `_fit_name`），只是长度上限不同（表名 64 / 字段名 30），
    保证同一个中文在两处转写结果一致、降级行为一致
  - 上限是**唯一**的降级触发条件，不按"中文字数"另设阈值，规则确定可测
  - **降级只在全拼超 30 字符时发生，也就是表头至少 7~8 个汉字，缩写串本身就有一串长度，
    碰撞概率很低**：拿本数据包 310 条真实中文列注释实测，**碰撞 0 组**
    （`时间`/`实际` 这类短表头全拼只有 6~8 字符，根本不会走到降级分支）
  - **数字与单位音节在降级时整段保留**，不跟着取首字母——否则
    `降水量≥1.0mm` / `≥10.0mm` / `≥100.0mm` 会被压成同一个 `...1...`，
    而这类数字恰恰是列名的区分点。保留后是 `lnyrjsl10mmpjrs` / `...100mm...` / `...1000mm...`
    （同一串里的 `(d)` 是括号注释，按上一条先剥掉，不参与降级）
  - 万一仍然撞名，靠 `_2`、`_3` 保证建表合法，含义可在「生成表结构预览」里改
- **命名开关：全拼/首字母、小写/大写**（图形版「Excel 导入」页前缀输入框右侧两颗勾选框，
  命令行 `--initials` / `--upper`，两条 Python 线与 Java 线都有）：
  - 图形版两颗默认都勾选，新加文件直接按「首字母 + 大写」起名；取消勾选后分别回到
    全拼、小写。命令行不加 `--initials` / `--upper` 时仍是全拼、小写
  - 「表名与字段名取拼音首字母」勾上后整名取各音节首字母（`订单金额` → `ddje`、
    `水库基础信息` → `skjcxx`）
  - 「表名与字段名转大写」勾上后输出全大写（`ding_dan_jin_e` → `DING_DAN_JIN_E`、
    空表兜底 `T_IMPORT_DATA` / `COL`）
  - 大小写也作用于文件名括号里显式写下的英文表名（`（dim_reservoir_info）` → `DIM_RESERVOIR_INFO`），
    但不改结构定义 Sheet 里人工写的字段名，也不改手动输入的表名前缀
  - 两颗开关都对**之后添加的文件**生效，切换时日志各留一行提示；重复跑同一开关结果不变
  - 「SQL 脚本改名」页只保留「表名与字段名转大写」开关，默认不勾选；勾选后当前表名清单、
    表元数据与该页两份 Excel 一起大写显示，脚本正文不回写；已删除该页的拼音首字母开关
  - ⚠️ **对已有库重新导入的影响**：字段命名规则变更后，同一张表生成的列名与旧版不同
    （旧 `dingdanjine` → 新 `ding_dan_jin_e`）。若目标库里表已存在，默认行为是跳过建表，
    随后 `INSERT` 会报 **1054 Unknown column**。要么勾「覆盖已存在表（先 DROP 再建）」重建，
    要么在表结构预览里把字段名改回旧列名。老数据表建议先备份再重导
- 类型推断规则（**全量扫描所有数据行**，不做抽样，最长行/异常行不会漏判）：
  - 日期时间对象或含时间的字符串 → DATETIME
  - **金额语义列 → `DECIMAL(16,2)`**（见下方「金额语义识别」），不走整数分支
  - 纯整数 → INT，溢出则 BIGINT；连 BIGINT 都装不下的整数改用 `DECIMAL(n,0)`，
    超过 MySQL 65 位精度的退为文本并在日志里说明（8 位纯数字如 `20230101`
    也按数值处理，编码列不会误判为日期）
  - 日期对象或带分隔符的日期串 → DATE
  - 含小数 → `DECIMAL(p,s)` 按**实测数据**定宽：`s = 实测最大小数位`（下限 2、不截断），
    `p = max(实测最大整数位 + 2, 4) + s`。上限取 MySQL 的真实上限（总精度 65、小数 30），
    不再把总精度硬压到 30——旧上限会把 14 位整数 + 18 位小数压成 `DECIMAL(30,18)`，
    实测到的整数位被挤掉，写入时就是 `1264 Out of range value`；
    超过 MySQL 上限的列退为文本并在日志里说明。
    旧版一律给 `DECIMAL(20,6)` 已废弃——那会让 2 位小数的普通列白占宽度，
    又不足以表达 7 位小数的经纬度列
  - 文本：按「全量最大 UTF-8 字节 + 20% 余量」向上取整到常用档位（64 ~ 16383）→ VARCHAR(n)；
    超过 16383 字节 → TEXT，超过 65535 字节 → MEDIUMTEXT；全表 VARCHAR 共享 60000 字节
    行内预算，预算不足的大文本自动退为 TEXT，保证建表不报 Row size too large；
    带前导零的整数字符串（如 `007`）保持文本，不丢前导零
  - **整列一个值都没有时，按字段名关键字定类型**（只在这一列为空时生效）：
    金额/单价/价格/费用等 → `DECIMAL(16,2)`；日期 → `DATE`；时间/日期时间 → `DATETIME`；
    是否/有无/开关/标志 → `TINYINT(1)`；率/比例/百分比/占比/系数/倍数/权重 →
    `DECIMAL(18,6)`；得分/评分/分数/成绩 → `DECIMAL(10,2)`；经度/纬度/坐标 →
    `DECIMAL(18,8)`；长度/面积/体积/重量/温度/频率等计量 → `DECIMAL(18,4)`；
    数量/个数/人数/次数/库存/户数等计数、年龄/工龄/年限、序号/排名、年份/月份/季度 → `INT`；
    其余 `VARCHAR(64)`。英文按成词匹配（`create_date`、`qty`、`is_deleted`、`longitude`
    命中，`update`、`birthday` 不误中）。金额优先于其他语义；显式比率词优先于计量词，
    裸「率」放在计量词之后，所以频率、功率按计量，容积率按比率。有值的列照旧按数据判定，
    结构定义 Sheet 里人工写的类型优先；每条按名定类型都写进
    `[类型修正] … 按表头语义调整` 日志行
- **金额语义识别**：纯值判定会把"订单金额"这类列在样本恰好为整数时判成 INT，金额被砍掉小数位
  （Excel 里 `100` 常以 `100.0` 存储，整数值浮点也会被认成整数）。因此在值判定之上加一层
  **表头语义修正**：中文表头或英文字段名命中金额关键词的数值列，一律用 `DECIMAL(16,2)`。
  - 命中示例：金额 / 单价 / 价格 / 均价 / 报价 / 成交价 / 结算价 / 总价 / 费用 / 成本 / 余额 /
    工资 / 补贴 / 收入 / 支出 / 付款 / 预算 / 税额 / 利息 / 保费 / 市值 / 销售额 / 利润 /
    欠款 / 贷款 / 保证金 / 押金 / 电价 / 水价 / 运价 / 票价；
    英文 `amount amt money price cost fee salary wage income expense balance budget
    revenue profit payment charge fund tax interest capital`
  - **只收成词的关键词，不认裸「费」「价」二字**：`费县`（地名）、`评价` 不会被误判成金额
  - **比率类一律否决**：表头含 率 / 比例 / 百分比 / 占比 / 增速，或名字含
    `rate ratio percent pct share` 的列不算金额——`年利率`、`interest_rate`
    按实测小数位定宽（否则 4 位小数被压成 2 位，数据就改了）
  - **绝不截断实测精度**：`结算金额` 若实测有 4 位小数，给 `DECIMAL(18,4)` 而不是 16,2；
    `总金额` 大到 16 位整数时自动放宽为 `DECIMAL(18,2)`
  - 语义层改变了纯值结论时，日志会单独打一行说明，不偷偷改：
    `[类型修正] 订单表.xlsx 共 1 列按表头语义调整：\n    表头「订单金额」含金额语义，样本值虽为整数，仍按 DECIMAL(16,2) 而非整数类型`
  - **结构定义模式（元数据 Sheet）不受影响**：人工写了 `INT` 就还是 `INT`，语义层只服务"从数据推断"
  - 推断结果都可以在「生成表结构预览」里逐列改
- 数值列中无法转换的值按 NULL 写入，并在日志中汇总告警（含列名、数量与行号示例）
- Excel 全空行自动剔除，不会导入整行 NULL 的垃圾数据；**整列没值的字段看表头**：
  表头写了字（含 `*标准名称` 这类必填标记）就照旧保留并在日志点名，
  表头空着的 `Unnamed` 列才丢
- **表头整行一个格都没写字**的模板也照样导入：pandas 遇到这种行会把**列宽一起丢掉**
  （实测 `columns` 只剩 0 个），所以判"一列都没有"之前要回原始工作簿问一次第一行有几个格
  （`_first_row_width`：xlsx 用 openpyxl `read_only` 取首行，`.xls` 用 xlrd 的 `ncols`）。
  问得到宽度就按它兜底出同样数量的空表头列，字段名走 `col` / `col_2` / `col_3`，
