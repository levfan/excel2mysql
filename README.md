# <img src="assets/app_icon.png" width="44" height="44" alt="excel2mysql 图标"> Excel → MySQL 批量导入工具

把一叠中文表头的 Excel 直接变成 MySQL 里的表：表名与字段名由中文自动转拼音，中文表头整句留作字段注释，类型与长度按全量数据实测推断，然后批量建表、分批插入。当前版本 v3.3.1，许可 MIT（见 `LICENSE`）。

丢一个目录或 ZIP 进去就行，这些判断它替你做完：

- 字段名转成 `ding_dan_jin_e`，字段注释仍保留原表头「订单金额」
- 文件名写成 `水库基础信息（dim_reservoir_info）.xlsx` 就直接用括号里的英文名；没写就整名转拼音，超过 64 字符自动降级成拼音首字母
- 类型按整列真实数据判，不抽样；金额列给 `DECIMAL(p,s)`，文本列按全量最大字节加余量给 `VARCHAR(n)`
- `.xlsx` 与 `.xls` 都吃，ZIP 自动展开，顶部标准的两行合并表头自动压成一行
- 一张表失败不阻断其余表；日志一行读完整件事，行首是 `+ [OK]` / `- [INFO]` / `! [WARN]` / `x [ERROR]`，MySQL 错误码直接写在行里
- Windows 命令行版把 `.sql` 默认只登记、不执行，加了 `--run-sql` 才跑，**绝不静默执行**脚本；Java 那条线相反，动作由路径类型决定，给 `.sql` 就直接执行——用它之前先确认这一点

三个包共用同一套解析与建表口径。

## 1. 选哪个包

| 你的场景 | 用哪个 | 系统要求 |
| --- | --- | --- |
| 日常在 Win10 / Win11 上导入，要边看边改表结构 | `excel2mysql.exe` | 64 位 Windows 10 1809 及以上 |
| 机器只有 Windows 7，或要放进批处理无人值守跑 | `excel2mysql-cli.exe` | 64 位 Windows 7 SP1 及以上，且系统有 UCRT 补丁 |
| Windows 7 上仍要图形界面，或数据库口令含中文 | `excel2mysql-java-3.3.1-win64\启动.bat` | 64 位 Windows 7 及以上，Java 运行时随包 |

解压即用，目标机不需要装 Python、Java 或数据库驱动。**图形版与 Java 版界面功能等价**，选哪个只看系统新旧、以及口令里有没有中文。

三条线的产物都是整目录，**只拷 exe 出去跑不起来**，分发时整个文件夹一起给。

Java 包也能命令行跑，老机器上要用批处理又不想装 Python 就走这条：`jre\bin\java.exe -jar excel2mysql-3.3.1.jar <路径> -c conn.ini`。

这条线另有 `--no-sql`（跳过 `.sql`）与 `--no-excel`（跳过 Excel 建表导入）：给一个目录时两件都做，要排除哪一件就点哪个开关；首个参数给 `--gui` 就是起界面。Windows 命令行版独有的 `--run-sql`、`--swap-prefix`、`--drop-if-exists` 在这里不认，敲了会报未知选项。

## 2. 30 秒跑通

图形版（`excel2mysql.exe`）：

1. 双击打开，在上方填主机、端口、用户、口令，点「连接并加载库」选目标库
2. 把 Excel 或 ZIP 拖进虚线区，等它解析完，在「待导入文件」表里逐字段改列名和类型
3. 点「开始导入」。落库前想核对结构就点「生成表结构预览」逐字段改，想先看建表语句就点「预览 DDL」，这两步都不写库

命令行版（`excel2mysql-cli.exe`），按这四步走：

```bat
excel2mysql-cli.exe --version
rem 先看能不能打印 excel2mysql-cli 3.3.1：能，说明系统层面进程与依赖都起得来

excel2mysql-cli.exe D:\台账目录 --dry-run
rem 只看会建成什么样，完全不连库，逐张表输出一句 CREATE TABLE

excel2mysql-cli.exe -c conn.ini --check
rem 只连接并列出可导入的库名，用来确认网络与凭据没问题

excel2mysql-cli.exe D:\台账目录 -c conn.ini -d ods_data --log 导入.log
rem 真导：批量建表并分批插入，日志同时写进 导入.log
```

`--dry-run` 与 `--check` 都不改库里任何东西，第一次上机就靠这两步把环境与口令验完。

支持哪些输入：

| 输入 | 会怎样 |
| --- | --- |
| 单个 `.xlsx` 或 `.xls` | 一个文件一张表；任一 Sheet 的表头里有「字段名、数据类型」这类列，就按人工定义建表，位置不限 |
| 目录 | 递归收目录里的 Excel（`--no-recursive` 只取一层）；Windows 命令行版遇到同目录的 `.sql` 只登记，加 `--run-sql` 才执行 |
| `.zip` | 展开包内 Excel 逐个导入，压缩包本身不进清单 |
| 表头有两行合并 | 顶部标准的两行合并表头自动压成 `父-子` 一行；数据区里的合并区一律拒绝导入，日志给出具体位置 |

## 3. 连接信息

把连接信息写进程序同级的 `conn.ini`，之后每条命令只要 `-c conn.ini`，口令不会留在命令历史里：

```ini
[mysql]
host = 127.0.0.1
port = 3306
user = root
password = 改成你的密码
database = ods_data
```

段名接受 `[mysql]` 与 `[connection]`；`database` 留空就是只连库不选库；配置文件读不了时告警一句并退回默认值，命令照常跑完。

优先级从高到低三处：命令行参数（`--host` `--port` `--user` `--password` `-d`）→ 环境变量（`E2M_HOST` `E2M_PORT` `E2M_USER` `E2M_PASS` `E2M_DB`，日志只说「取自环境变量」不回显值）→ 配置文件（`-c FILE`，或不给参数时自动读程序同级的 `conn.ini`）。

**两条 Python 线的口令不能含中文**（pymysql 按 latin-1 编码口令，中文口令会连不上）；口令里有中文就改用 Java 版，它走 JDBC，没这个限制。

## 4. 常用开关速查

完整清单以 `--help` 为准，这里只列真会用的几个：

| 开关 | 作用 | 要知道的坑 |
| --- | --- | --- |
| `--dry-run` | 只解析并打印建表 DDL，完全不连库 | 对 `.sql` 也只报语句数，不改库 |
| `--check` | 只连接并列出可导入的库名 | `-d` 指的库不存在会直接报错退出 |
| `--run-sql` | 把输入里的 `.sql` 执行到目标库 | 每个文件一个事务，全部语句成功才提交；不加时 `.sql` 只登记 |
| `--prefix ods_` | 给全部表名加前缀 | **是加一段，不是改名**：基于基础表名重算，重复跑不叠加。分隔符要**自己写上下划线**，末尾没写 `_` 时日志会警告一句 |
| `--swap-prefix change` | 替换表名首段：`ods_t_order` → `change_t_order` | 名里没有下划线、或以 `_` 开头的表不动，并逐条列在日志里 |
| `--drop-if-exists` | 建表前先 `DROP TABLE IF EXISTS` | **会真删掉同名表和它的数据**，且 DDL 在 MySQL 里隐式提交、不随事务回滚；只作用于 Excel 建表这条路，脚本内容不改 |
| `--log 导入.log` | 另存一份 UTF-8 日志文件 | 追加写，同一份文件可以反复跑多轮 |
| `--quiet` | 控制台只留警告、错误和汇总 | 日志文件仍记全量，排查靠它 |

同一批里两个文件算出同名表时自动加 `_2`、`_3`，不会互相覆盖。

## 5. 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 全部成功 |
| 1 | 用法或配置错误：参数冲突或非法、配置文件缺失、未指定目标库、没有任何可解析的文件 |
| 2 | 有输入文件解析失败，其余文件照常处理 |
| 3 | 连不上 MySQL，或目标库不可用 |
| 4 | 有表建表或导入失败，其余表照常处理 |
| 5 | 有 SQL 脚本执行失败，该文件已回滚，其余文件照常处理 |
| 130 | Ctrl+C 中止，已完成的表与文件保留 |

同时出现多种问题时取最严重的一档。批处理里从大到小判断：

```bat
if errorlevel 5 echo 脚本执行失败，去看日志
```

## 6. Windows 7 起不来怎么办

命令行版在老机器上装好就能跑，卡住多半只差一样东西：系统 UCRT（补丁号 KB2999226，KB4019990 也带它）。缺它的症状是进程还没进程序就报 `ImportError: DLL load failed while importing _socket`。

按这三步定位，一次只排除一层：

1. `excel2mysql-cli.exe --version` —— 打不出版本号就是系统缺依赖，先跑包里 `win7_sp1_patch\3.check_win7.bat` 自检，再以管理员运行 `4.install_minimal.bat` 补齐，重启后回到这一步
2. `excel2mysql-cli.exe -c conn.ini --check` —— 报 `x [ERROR]` 带 MySQL 错误码就是网络或凭据问题，与机器无关
3. `excel2mysql-cli.exe D:\台账目录 --dry-run --log 试跑.log` —— 这一步红说明是文件本身的问题，日志里点名是哪个文件、哪一列

命令行版已在 Python 3.8.10 旧栈全量通过并与 3.12 新栈逐条对平，但没有在真机 Windows 7 上跑过，第一次上机请务必先用 `--version` 自检。
